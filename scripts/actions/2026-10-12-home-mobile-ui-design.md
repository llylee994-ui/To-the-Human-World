# 手机主页 UI 改版方案（待确认）

依据：用户手机截图与 2026-10-12 反馈。目标是保持油画海港小屋的沉浸感，使状态、操作和提示融入场景。本文件记录前端方案，不修改剧情、存档规则或美术排版。

## 核对结果

1. `AppView.lua` 的 `homeHud` 为全宽深色栏，`nextDay` 使用默认 UI.Button，蓝色结束当天按钮属于游戏控件。
2. 平台圆点/退出胶囊是另一层。`main.lua` 使用 SafeAreaView，但没有设置 `nativeMenuInset=true`。当前 SafeAreaView 默认不合并平台胶囊 inset；项目引擎文档和库实现均明确这一点。
3. `GameState` 生成 migrationNotice，`PlayModel.New` 复制到 message，AppView 无区分地放进常驻 36 高 playMessageArea。因此诊断长文直接进入玩家主页。
4. 当前主美术为 1920×1080，LayoutGeometry.Fit 使用等比 contain。项目配置 screen_orientation=landscape；2026-10-10 横屏前端计划明确用户已改为横版，早期 fyyAGENT 竖屏说明属于旧目标。
5. 用户图片为 2412×1080 横屏比例。可以确认宽屏余边，但不能用该图证明竖屏黑边或宿主旋转能力。
6. HomeView 的 outline 只在 developer && inspect 时绘制。正式入口只有透明热点，没有玩家提示；现有 manifest 已有 8 个交互对象的中文 label。
7. 绿色内部开发提示在 scripts/assets/配置及相关引擎文档中未找到。疑似测试宿主叠层，尚未证明来源；当前公开 Maker 能力未发现水印位置设置。需另查手机测试宿主，不通过裁切主场景或覆盖图块掩盖。

## 可选路径

- 推荐：轻量手绘 HUD。保留场景和热区，在安全区放少量纸签与木牌；实现量适中，统一主页/海边及浮层操作。
- 更沉浸：金币与日期完全嵌入场景道具。需新增排版并重新验收热点，手机小字与对比度风险更高，当前不采用。
- 最小修补：换颜色、移除技术长文。可快速缓解问题，但整条现代 HUD 的结构仍割裂，不作为最终交付。

## 推荐设计

### 状态与操作

- 保留横屏游玩目标与 1920×1080 原构图，按安全区域等比完整显示。保持图层、入口与热区几何一致，余边采用协调的深木色；不为铺满 20:9 裁掉网兜或案件袋。
- 顶部全宽深色栏改为紧凑状态纸签：左上真实金币和“第 N 天”，暖纸色、深褐字、细暗边，与木头、旧信纸和黄铜美术取色一致。
- 结束当天改为手绘木牌/纸签按钮；沿用现有确认与跨天规则。标签保留“结束当天”，不改变操作含义。
- 返回、关闭、商店、捕捞、跳过等游戏按钮使用同一套样式与按下/禁用状态。文字仍由 UI 控件绘制；不把动态字烘焙进素材。
- 交互 UI 明确避让设备安全区与 sdk:GetNativeExitMenuRect；背景独立于额外交互 inset。优先用局部 SafeAreaView 避让胶囊，必要时根据矩形局部调整，避免胶囊导致整个场景继续缩小。平台胶囊保留宿主样式，不把它伪装成游戏功能。
- 按钮有效触摸区域至少 44×44 UI 基准像素，移动端标签保持可读。复用现有可用 MiSans，不加入未提供的字体。

### 玩家消息

- 迁移诊断保留在开发日志/状态来源，玩家展示层转换为简短说明：“进度已更新。今天先休息吧，明天再去海边。”只表达该迁移状态，不伪造获得次数。
- 有旧选料需要重选时，在炼药入口附近解释需要重新选料；不把所有迁移细节塞进主页。
- 首页取消永久底栏。普通反馈改为可消退的纸签提示；空消息不占空间。
- 保存失败、读档失败、进度待核对等阻塞问题必须保持可见、保留重试与业务锁定，不能统一超时隐藏。玩家提示使用通俗文字，技术代码与事务数据留在日志。
- 用独立前端消息展示/映射模块承接；保留业务诊断与当前存档，不改 core/systems/data，不清档或补次数。

### 可交互物件

- 首次进入展示短引导“点物件，看看有什么”，并给网兜、抽屉、锅、词条盘等交互对象加短纸签提示。
- 首次提示约 5 秒后收起；保留“提示”入口，玩家可再次查看全部可交互物件。点击后短暂出现对应功能名与柔和反馈；无循环霓虹、开发 ID 或热区矩形。
- 提示标记仅来自实际交互 manifest，装饰花瓶/剪刀不标记。标记不拦截物件点击，不遮住锅口、信纸正文和门洞；演出期间隐藏引导。
- 手机竖向 viewport 作为降级状态显示“横过手机，走进小屋”，暂停场景点击。横屏配置不能证明所有宿主支持强制旋转，需真机验证。

### 测试提示层

绿色内部测试提示先定位具体宿主版本与叠层来源。若属于可配置的自有层，则放到测试入口或角落；若由平台强制注入，明确记录宿主限制。正式发布形态是否保留该层要用真实发布环境核实，不能假定正式版一定消失。

## 实施与验收

先做玩家信息清理和胶囊避让，再统一 HUD/按钮素材与样式，最后接物件提示。使用 Maker 图片工作流生成确有需要的纸签/木牌纹理，保存来源回执。保留所有未提交的剧情和海边改动，不提交或远端构建。

专项检查应覆盖：迁移说明不含技术诊断且保存原诊断；阻塞错误不消退；长数字、小屏文字、平台矩形避让；8 个真实热点与提示一致；提示不吞输入；原主页、门洞推进和捕捞跳过/中断回归。图像证据应分别记录离线样稿、Windows 原生窗口和手机实际截图，桌面窗口不可替代真机验收。

代码/资源批次后执行 preview status；仍运行则刷新并读取日志/check，已停止不自动启动。两条既有引擎 DDS/DLL 错误单独记录，不宣称整体 check 已通过。
