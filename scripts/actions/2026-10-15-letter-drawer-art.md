# 来信抽屉：方形俯视素材接入

用户授权选择合适图片接入试用；本轮不使用子代理，不提交或远端构建。

## 实现

- LetterDrawerArt 使用 assets/image/letter-drawer-v01 下的方形俯视抽屉、两种信纸、标题铜牌、关闭/返回按钮、分离轨道与滑块、卷轴/包裹。抽屉原图已经有拉手，不重复叠加独立拉手。
- 正方形面板居中，按安全区可用高度的 94% 和宽度取较小值，图片等比显示。保留原 0.34 秒下滑/收回及原有关闭、取消路径。
- 原始 PNG 不修改；通过裁剪容器和可见边界投影处理图片透明留白。仅滚动轨道/滑块沿纵向适配。
- 宽面板两列，面板宽度不足 600 UI 基准像素时单列；信件展示真实标题、寄信人和未读/可剪/已读状态。未读用蜡印纸，已读用展开纸。
- 列表使用 UI.ScrollView 承接滚轮/触屏滑动，铜滑块随 onScroll 更新；装饰滑块自身不提供拖动交互。无溢出时隐藏滑块。
- 只修改 LetterDrawer.lua、LetterDrawerArt.lua、对应专项检查；未修改 PlayModel、业务模块、数据或玩家存档。

## 验证

- 原专项 85 项基线通过；更新期望后先出现缺少铜叉素材的预期失败，再实施接入，最终 88 项通过。覆盖开合、信件状态图片切换、读信、关闭、空态、布局边界、浏览不写盘，以及标题/信纸文字的真实排序方法。
- 相关阅读/纸面、词条栏、记录书回归通过。两个修改的生产 Lua 文件通过 Maker LSP diagnostic 查询，未返回 Error。
- export_drawer_preview.py 读取实际 Art.Fit 和图片边界，渲染 1280×720、800×450 两张离线装配预览并实际查看。示例来自正式内容配置，不读取或修改玩家存档。路径：.tmp/letter-drawer-art-preview/。
- 离线预览不是 Yoga、引擎渲染、真实触控或手机证据，字体/换行/输入仍需原生补验。
- 本地预览存活，代码批次后按规范刷新并读取日志。起初停在 DownloadInitialPackage，随后资源下载完成、项目成功启动。既有 DaySpecularHDR.dds / themis_x64.dll 错误仍使官方 check 返回 FAIL，不声明官方检查全绿。
- 原生验收开关 letterDrawerProbe 仅打开玩家当前抽屉，断言前后快照相同。实际窗口 1450×815，抽屉 766×766 UI 单位。当前玩家没有信件，原生只验证空态，不虚构收信。
- 原生发现标题有正确内容和 360×30 布局却被牌子遮住。定位到 Widget.GetRenderChildren 对同 zIndex 的不稳定排序；给背景、物件、文字、按钮建立明确层级，信纸文字也覆盖同一问题。最终 reload 14 的 native-drawer-final.png 已查看，标题正确显示，日志顺序检查通过。
- DevChecks 默认开关已恢复 false，普通玩家入口会再次刷新。新增 tests/LetterDrawerNativeProbe.lua 及 NativeProbe 的显式入口供以后复查，不自动收信、不推进天数、不修改玩家存档。
- 原生与离线证据保存在 .tmp/letter-drawer-art-preview/；手机、原生有信长列表/滚动及真实点击仍需单独补验。Windows 后台 PostMessage 没有可靠触发，不当成玩家点击失败或成功的证据。
