## 1. B1 要交付什么

让玩家保存过的进度真正恢复，让保存失败不会毁掉上一份有效进度，并建立一份可供后续订单使用的材料与金币账本。

完成后首先能看到：保存第 5 天、推进到第 6 天、点击读取，主界面和调试面板都恢复第 5 天；退出重进也保持保存结果。之后接入真实开局配置，确认四种材料各 3 份、只拥有旧锅，账本试算不改变正式库存。

本批不开发炼药页面、正式订单发货、回信、评分算法、商店、身份或完整剧情回溯。R1 修正已经明确评分顺序，留给 B3/B4 实现，不在 B1 顺便做评分。

### 两个交付状态

| 状态 | 必须完成 | 能否等同完整 B1 |
|---|---|---|
| B1 技术基础完成 | 三项读档修复、可靠保存与错误状态、统一恢复入口、隔离槽故障检查 | 不能；尚未接真实账本配置时必须这样标记 |
| B1 完成 | 技术基础 + 真实初始账本 + 最小 Economy + 存档结构/迁移校验 + 基础状态真实重启验证 | 可以交给 B2～B5 使用；仍不等于整单幂等或 A1～A19 全过 |

待确认对象在 B1 验证的是完整保存/读取、失败保护和结构校验能力。真实 Order 的确认、重置、禁止操作、发奖与人物变化在 B5 由实际模块联调，不能用本批夹具代替。

## 2. 先后顺序与依赖

```text
开发：P1 三项复现 → P2 统一恢复 → P3 可靠保存
                                      ↓
                                P5 整体保存/迁移 → P6 验证交付
                                      ↑
      P4 最小账本 ← 队友 C1 开局包 ──────┘

队友：C1 开局包 → C2 首单规则与报酬 → C3 事实/回信/评分
                    C2、C3 可与程序 P1～P5 并行准备
```

P1～P3 不等待剧情或回信。P4 可以先用明确标记的技术夹具验证纯计算，接入正式开局时必须换成 C1。P5 的正式 v2 初始化/迁移还需要 B0 要求的完整初态与相容内容版本；缺少时返回配置或迁移待处理，不用空对象伪装配置齐全。

## 3. 程序开发任务（开发队友负责）

下列路径相对本文件所在的 `scripts/`。新文件为计划位置，不表示当前已有相应 API。

### P1：先在隔离存档槽复现三项问题

修改/新增：`debug/SaveSystemTest.lua`、`debug/fixtures/B1Fixtures.lua`，由 `debug/SelfTest.lua` 接入专项入口。

- 使用固定、专用的 B1 测试槽名；不得写默认 `slot1`，不得批量删除用户存档。
- 保存 v1 嵌套 `{gameFlow=...}`，设置 day=5、canSalvage=false 和非默认主线阶段，经与正式启动共用的恢复路径读取。
- 分开记录“取错 gameFlow 层级”和“false 被默认值覆盖”，避免第一个错误掩盖第二个。
- 第三个场景：保存第 5 天，推进到第 6 天，调用调试读取的实际入口，检查流程状态和两个天数标签；只打印“读取成功”不算恢复。
- 每项输出输入、实际值、期望值和失败原因。尚未修复时保留真实失败证据，不只写静态预测。
- 专项检查不自动运行破坏性故障注入；只在指定调试入口执行，并在成功/失败后恢复测试前内存状态。原历史自检继续使用自己的隔离槽。

出口：三项风险分别得到可重现结果；如果某项未复现，记录实际原因后调整测试，不为了凑三项失败修改正确代码。

### P2：统一启动与调试的保存/恢复入口

修改：`core/GameFlow.lua`、`main.lua`、`debug/DebugPanel.lua`；新增 `core/GameState.lua` 作为整体状态协调入口。

- `GameFlow.Init` 只接流程子表；明确缺字段默认值与非法类型处理，显式 false 保持 false。不要用 `boolean and value or true` 恢复布尔值。
- `GameState` 统一承担读取、整体校验、安装状态和刷新通知。函数名在实现时按 B0 的 Result/Load 约定统一；启动和调试按钮必须调用同一路径。
- 调试面板通过注入的保存/读取回调操作，不再自行调用 SaveSystem 后只打印结果，也不在按钮里拼另一份存档。
- 全部状态校验成功后才安装；成功后发送一次 `SaveLoaded` 供标题和调试面板刷新，不用伪造 `DayStarted` 刷新显示。
- 将“文件不存在、已载入、损坏、版本不支持、需迁移”分别显示；读取失败不清空当前可用内存，更不能随后把默认值自动写回损坏文件。
- 启动必须检查 Data.Load 的结果。错误状态保留可读诊断入口，禁用保存、跨天等会改变进度的入口；不得以默认成功继续运行。

出口：P1 的三个恢复场景转为通过；启动与按钮的日志、内存状态、界面数值一致。

### P3：实现可靠写入与可识别的读档状态

修改：`core/SaveSystem.lua`、`debug/SaveSystemTest.lua`；扩展调用者对错误结果的处理。

1. 写文件前先验证待保存数据并保护性编码；函数、userdata、循环表、非有限数值等失败不能先截断正式文件。
2. 按 B0 保留 Save 的首个 boolean 返回值，错误改为结构化信息；Load 区分 new/loaded/migrated/corrupt/unsupported/migration_required。status 的实际表结构统一给所有调用者，避免一处按字符串、一处按表解释。
3. 在专用槽验证文件协议。优先评估“双份完整快照＋明确的提交选择记录”；只有实测满足同等失败语义时才采用临时文件替换。查本地 File/FileSystem 文档与声明，不因 Rename 返回 boolean 就假定跨平台原子性。
4. 检查 WriteString 返回值、关闭和读回后的完整性，保留上一份已验证快照。Load 不得只凭“时间较新”选中写了一半或未正式提交的候选。
5. 在编码失败、写入失败、读回失败、提交选择前后中断处分别验证磁盘与内存。Save 返回失败后，重启不能悄悄选择本次未确认候选；Save 成功后重启须能选择同一新快照。
6. 只有在文件协议故障检查通过后才替换默认槽写入路径。任何提交状态不确定的边界必须在实现中解决并补案例，不能打印失败后继续接受下一次结算。

出口：故障后仍能恢复明确的一份完整状态；成功/失败返回值与重启选择一致。协议选择及证据写入实施行动记录，这属于技术验证，不需要重新确认已接受的业务规则。

### P4：接入最小 Economy 账本

新增：`systems/Economy.lua`、`debug/EconomyTest.lua`；通过既有 `data.content` 读取内容方提供的 C1。

- 正式账本仅保存金币、原料份数、特殊物品实例和已拥有设备；词条实例继续归 WordToken，不能在 Economy 复制一份词库存。
- 实现 B0 约定的快照校验、深副本读取/恢复、`PlanSettlement`。输入状态、用量和奖励，输出候选账本与差异，不修改正式状态、不保存、不发奖励事件。
- 拒绝负数、非整数、未知材料、重复特殊物品实例和超库存消耗；检查输入表在试算后没有被改写。
- 相同基准和请求重复计算得到相同候选，不累计扣料。正式结果的唯一提交由 GameState/后续 Order 协调，不能通过 MoneyChanged 监听器再次结算。
- 读取 C1 的开局金币和四种原料各 3 份；只拥有旧锅。旧档恢复必须用存档库存，不能每次启动重新赠送开局物资。
- 技术测试允许使用固定金额作为夹具，但与正式 Data 分离、明确标注；程序中不得把演算样例的 80/400 当开局或报酬。

出口：真实 C1 可以初始化账本；试算、失败、保存、恢复保持一致。此时仍没有可玩的发货按钮，也不宣称已经验证完整订单的重复确认。

### P5：接整体快照、版本与迁移

修改：`core/GameState.lua`、`core/SaveSystem.lua`、`main.lua` 及上述专项检查。

- 以 B0 §6 的完整 Envelope 为目标，不重新发明另一份状态表；schema、contentVersion、synthesisVersion 分别校验。
- `GameState` 为 core 的协调代码，不新增业务规则；依次请求模块的公共校验/快照接口，禁止外部直接改私有表。验证所有候选后才安装，安装失败不得留下部分模块已恢复、部分仍为旧值的状态。
- P1～P3 可先在原 v1 流程上修复；完整 v2 字段、真实初态和对应恢复器就绪前，不升级默认正式槽，也不把空壳存成 v2。未知业务块要报错并保留原档，不能丢弃后另存。
- v1→v2 保留合法 day/phase/canSalvage/mainStoryStage/deliveredOrders。新字段从已校验内容初态生成；数据不齐报 migration_required。
- v1 非零 deliveredOrders 但无订单明细时保留原档并提示迁移待处理，不清零、不伪造确认记录。将这一分支纳入专项检查。
- 为 accepted/brewing/pending 对象验证 false/对象互斥、基准版本、配方与候选完整性；用完整、显式标记的技术夹具验证往返保存。不能重算已保存的回信、事实或星级来“修复”不相容档。
- 模块尚未实现时，只能报告“结构/存储层检查通过，运行恢复未接入”；B2～B4 接入真实模块后补恢复适配，B5 验证整单行为。不能为让测试通过增加生产环境假模块。

出口：真实可用模块能统一恢复；完整 Envelope 的存储与版本检查有证据。任何未接模块的恢复项单独列待验证，不把夹具成功写成真实待确认玩法可用。

### P6：实际窗口与重启验证，整理交付

- 运行 Lua LSP 检查实际改动；处理相关 Error，不能用删掉正确判断掩盖类型问题。
- 按项目本地预览规范，在运行中的会话刷新并读取新日志；已停止的会话不擅自重启，实际启动测试按用户授权进行。所有预览命令明确指定工程绝对路径。
- 在真实引擎 File 上完成隔离槽保存、退出、重进，验证流程和账本；模拟 File 的检查需单独标记。
- 实际看窗口确认标题/调试面板同步、错误提示能读懂。中文继续使用 MiSans，不用无头白图断言 UI 渲染。
- 记录先前引擎资源/DLL 诊断是否复现，不把“12 项自检通过”当作预览全绿；环境故障与游戏逻辑错误分别记录。
- 交付变更、测试结果、未验证项、兼容说明和下一批接口。下表逐项记录实际结果，不能预先勾选。
