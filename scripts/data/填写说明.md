## 2. 通用约定

| 约定 | 说明 |
|---|---|
| ID | 非空字符串，全项目引用；中文显示名不作主键 |
| 类型 | 「非负整数」= 0,1,2…；「份数」= 正整数；「权重/小时」= 有限 number（禁止 NaN/Inf） |
| false 与缺省 | `false` 是有效值；只在 `nil` 时补允许的缺省。**不得**用 `x or default` 恢复布尔值 |
| 空集合 | 显式写 `{}`；「尚未交付」与「明确为空」必须区分 |
| 单位 | 时间一律「游戏小时」，不驱动现实等待；剂量时间参照 = **服药时刻 0** |
| 可保存数据 | 仅字符串、有限数值、布尔、纯表；无函数/userdata/循环引用；数组从 1 开始且稠密 |
| 错误 | 统一 `Result<T>` 判别表与错误码，见 B0 §2。内容校验负责「配置缺失/未覆盖」，运行校验负责「请求非法」 |

`ValidateStage1` 里 `potion.effects` 的取值约定：**药效表中缺某标签 ≡ 该标签权重为 0**（用于条件比较），
这不是「缺字段补默认」，而是 effects 的取值语义。真正缺配置（如缺时间 profile）一律报错。

## 3. 怎么写信（`letters.lua`）

### 3.1 两类信件

| 字段 | `kind = "order"` | `kind = "direct_followup"` |
|---|---|---|
| `cuttable` | 显式 `true`（正文必须有 `{{词}}` 标记） | 显式 `false`（正文不得有标记；正文由模板组装，本表可不写 `body`） |
| `requirement` | 必填（含 `tags`、`conditions`） | 不得配置 |
| `reward` | 必填 `{ currency = 非负整数 }` | 不得配置 |
| `directRuleSetId` / `ratingSetId` | 必填，指向 `followup.lua` | 不需要 |
| `followupTemplateId` | 必填 | 必填 |
| `address` | 必填 | 可选 |
| 出现方式 | 由 `appearCondition` 进普通队列 | 由 Order/Narrative 在发货后直接展示，**不进打捞队列** |

直接回信天然不可剪词、不可领附件；运行门禁仍要拦住「待确认期间剪后续词/领附件」的请求。

### 3.2 正文与可剪位置

- 正文用 `{{词}}` 标记可剪位置，标记内容必须与某条 `words[].displayText` **完全一致**。
- 位置 ID 由程序按正文出现顺序生成 `body:1`、`body:2`……**不要手写偏移**；编号一旦进入存档即固定。
- **改动已进入存档的信件正文（增删、替换或移动 `{{词}}` 标记）必须递增 `contentVersion`**：
  已保存的 `cutSpans` 按 `body:N` 指向旧正文，重排会让旧档的缺口、词条来源与正文错位。
  新增信件或新增词定义不改动既有位置，但也应在本文档登记并递增版本，避免与旧档解释混淆。
- 首信可剪词顺序已冻结为：累、笑、忘记、梦、安静、睡觉（2026-10-03 词条层第一批：第二处由「快乐」改为「笑」，`word_happy` 退役，happy 由「笑」承担；`ValidateStage1` 不查顺序，改动前先对齐文档）。

### 3.3 订单要求

```lua
requirement = {
    desc = "……",                -- 必须让玩家看得见全部字面条件
    tags = { sleep = 0.8 },      -- 最低效果权重
    conditions = { ... },        -- 见下表；未要求的属性不要写条目
    forbiddenEffects = {},       -- 没有禁止项时显式空表
},
```

`conditions` 的 kind（未知 kind 一律报错，不当「未要求」放过）：

| kind | 字段 | 语义 |
|---|---|---|
| `duration` | `minHours`, `maxHours` | 闭区间上下界，`minHours < maxHours` |
| `onset` | `maxDelayHours` | 生效延迟 ≤ 上限 |
| `workReady` | `workAfterDoseHours` | `onset + duration + recovery ≤ 工作间隔`；只判药效结束/恢复，不推断剧情能力 |
| `residualAt` | `effectId`, `atAfterDoseHours`, `maxWeight` | 在指定时刻采样残留（见 §4.3），超阈失败 |
| `forbiddenEffect` | `effectId`, `maxWeight` | 只限制订单明确禁止的标签，不自动禁止所有额外效果 |

首单 `letter_pa_01` 已填：`tags.sleep = 0.8`；`duration` 6~8 小时（已接受调试范围，含边界）；
`onset ≤ 3`；`workReady = 12`；`residualAt sleep @12h ≤ 0.4`；禁止效果显式空集。

### 3.4 报酬与出现条件

- `reward.currency`：本单固定报酬，**一至三星完全同额**；不从原料价格或星数推导。
  首单调试初值 `80`（复算见 §4.4）。
- `appearCondition` 现有键：`dayMin` / `dayMax` / `afterLetter` / `minDelivered` / `worldState`（阶段 1 先实现前两个）。

## 4. 首单数值（`stage1.lua`）

### 4.1 开局账本（C1）

| 字段 | 已接受调试初值 | 说明 |
|---|---|---|
| `contentVersion` | `"stage1-b0v0.2-r1"` | 非空；整包内容修订标识，与 `synthesis.version`、存档 `schema` 分开 |
| `initialEconomy.currency` | `30` | 非负整数；不采用经济演算示例的 80/400 |
| `initialEconomy.ingredients` | 四种原料各 `3` 份 | 海盐 / 夜露 / 灰烬草 / 干花瓣，缺一不可 |
| `initialEconomy.specialItems` | `{}` | 首信无附件，显式空集合；不得因特殊槽容量赠送物品 |
| `initialEquipmentId` | `kit_old_cauldron` | 与 `equipment.lua` 的 `owned` 一致：旧锅 true、铜锅 false |

`errorSamples` 是 Economy 初始化校验的负例断言（缺金币 / 负或小数库存 / 缺一种原料 / 未知材料 / 未知设备），
程序按 `path` 在 `initialEconomy` 副本上施加 `mutation` 并核对 `expectCode`；它们不是可运行配置。
**旧档恢复必须用存档库存，不能每次启动重新赠送开局物资。**

### 4.2 重复投料策略（C2）

| 策略 | 值 | 理由 |
|---|---|---|
| `repeatIngredient` | `true` | 同种原料可重复占槽：按 ID 聚合成一行、`quantity` 份数累加，每份占一格；槽位上限 2 已封顶，不产生退化配方 |
| `repeatWordDefinition` | `false` | 不同 tokenId 但同一 wordId 视为重复投料，返回 `DUPLICATE_NOT_ALLOWED`；同一 tokenId 跨槽始终非法 |

正式词必须显式填写 `words[].reusable = false`；后续新词同样一次性。确认本单并保存成功后消耗实际投入的主／辅来源卡，预览和本单重置不永久扣卡；旧单已确认消耗不恢复。复用策略与「重复占槽」分开，同词定义仍不得同锅重复。
同一正文位置只能剪一次，不同信件同名词是独立来源卡。历史获得与当前 available 库存分开；无名者只数可用定义／类别。内容提交前必跑 `python docs/验证/check_single_use_content.py`，误填 true 或省略 reusable 会报出词 ID；程序通用 reusable 字段保留，技术夹具不作为正式词策略。

### 4.3 时间属性（`attributeProfiles`）

```
durationHours    = baseDurationHours + mods.duration × durationHoursPerPoint
onsetDelayHours  = speedToDelayHours 按 mods.speed 精确查表   -- 漏项报错，不插值
recoveryAfterEndHours = 药效结束到完全恢复的固定小时数
```

| profile | 用途 | 调试值 |
|---|---|---|
| `sleep_basic` | 「睡觉」主词 | base 8 小时（已接受样板）、每点 +1 小时（干花瓣 +2 → 10 小时） |
| `tired_basic` | 「累」主词 | base 6 小时（调试初值，仅保证负例 F 可完整计算；正式值待校准） |

首单可达的速度修正 → 延迟映射（三者必须齐全）：

| speed | 0（无夜露） | 2（夜露×1） | 4（夜露×2） |
|---|---|---|---|
| delayHours | 2 | 1 | 0 |

**残留表语义**（`residualRules`，当前只声明 `sleep`）：

- 按「药效结束后的整小时」取点，`ratio` 为相对最终权重的残留比例；表必须从 0 开始、逐小时连续、非增。
- 采样点必须落在已声明点上；**采样时药效仍在（afterEnd < 0）按 1.0 处理；超出表尾（> 4 小时）按 0 处理**。
  两条都是显式声明，不是插值。
- 遗留为 `sleep`（0 → 0.6、1 → 0.3、2 → 0.1、3 → 0.05、4 → 0）。
- 未声明残留曲线的标签被订单采样时按缺配置报错（本包 `calm`/`dream`/`forget` 未声明）。

**首单时间假设的由来**：睡前约 21:00 服药、次晨约 09:00 上工，工作间隔 12 小时。
合规单（8 小时睡眠 + 2 小时生效 + 1 小时恢复 = 11 小时）留 1 小时余量；
干花瓣的 10 小时睡眠会同时触发 duration、workReady、residualAt 三项失败（样例 E）。

**未配置 `attributeProfileId` 的主词**：涉及时间换算的请求报 `CONFIG_MISSING`，不套用其他词的样板。
当前 30 个正式词均已配置主词 profile；上述缺配置报错只适用于未按要求填写的新内容／技术输入，不再把其余正式词称为缺 profile。

### 4.4 报酬 80 的复算依据

- 旅人路线：票 300，第 9 天前约 12 单可达、单均材料成本上限 40；漏做 2 单时下界
  `10 × (80 − 40) = 400 ≥ 300`，留 100 缓冲（与已接受验算示例形状一致）。
- 学徒路线：约 20 单一周目，收入 1600；家居 480 + 材料开销 ≤ 400，余量充足。
- 该值为**调试初值**；完整订单表排定后必须用逐日流水替换上述估算再校准。

## 5. 八步求值的已冻结边界（与 `synthesis.lua` 注释同步）

1. 第 2 步「已存在于主轴」= **当前已合并的标签集**（含此前辅助词并入的标签），
   两个辅助词引入同一标签时，第二个照样获得 `sameTagBonus`。
2. 第 7 步副作用追加标签**按加法叠加**（不替换、不取最大值），追加值不再受第 5 步强度缩放；
   同一规则只触发一次；第 7 步新增/改变权重的标签按最终权重**重新套用同一张区间表定级**。
3. `intensityTiers` 为**闭区间上界**：`weight ≤ max` 命中首个区间；超过最后边界（> 99）报配置覆盖错误。
   权重被负修正压到 ≤ 0 的标签从结果中移除；mods 单项允许范围 −4 ~ +4。
4. 原料无某一项 mods 时按加法单位元 0 处理（缺单个键 ≠ 缺整个必填配置）。
5. 时间换算只读**主词**的 profile；辅助词目前不携带 profile。

副作用交叉示例：灰烬草 `sideEffect = 2` 触发 `se_dream`，追加 `dream = 0.4`（不缩放，微弱），
且**不构成「梦到母亲」**——「梦到母亲」阈值是 `dream ≥ 0.6`，0.4 只产生「零碎多梦」事实。
这正是样例 G2/G3 覆盖的交叉点。

## 6. 事实与回信（`followup.lua`）

### 6.1 事实规则 `directRules`

```lua
{
    id, ruleSetId, priority,
    when = { { source, path, op, value } },   -- 全部满足
    unless = { { source, path, op, value } }, -- 任一满足即排除；可省略
    facts = { { id, subjectId, objectId, value, important } },
    changes = { { path, op = "set"|"add", value } },
}
```

- 运算符只用 `eq / ne / gte / lte`；来源限定 `potion.effects`、`world.npcs`、`context`、`facts`。
- 规则全部针对**同一输入快照**匹配，再汇总更改；规则之间不读本批新事实。
- `changes.path` 从 `world.npcs.<npcId>.<字段>` 写起，必须指向 `npcs.lua` 已声明字段。
- `objectId` 必须是人物声明的私人记忆对象（本包只有 `mem_mother`）；遗忘只作用于这里声明的对象。

本包 7 个事实：

| 事实 ID | 含义 | important | 产出条件（摘要） |
|---|---|---|---|
| `fx_sleep_improved` | 睡好 | 是 | `sleep ≥ 0.8` |
| `fx_morning_work_ok` | 次晨有力气 | 是 | 同上 |
| `fx_dreamt_mother` | 梦到并认出母亲 | 是 | `dream ≥ 0.6` 且 `forget < 0.6` |
| `fx_mother_memory_faded` | 母亲相关记忆变淡 | 是 | `forget ≥ 0.6`（同时把 `mem_mother.state` 置 `faded`，药效结束后保留） |
| `fx_dreamt_figure_unclear` | 梦里认不清背影 | 是 | `dream ≥ 0.6` 且 `forget ≥ 0.6` |
| `fx_self_distressed` | 本人难受 | 是 | 同上（D 的一星依据，不是「有遗忘就扣星」） |
| `fx_restless_dreams` | 零碎多梦 | 否 | `dream ≥ 0.4` 且 `dream < 0.6`（灰烬草交叉） |

互斥组 `xgroup_pa_dream` 声明「认出母亲」与「认不清」不得同时成立；规则条件已保证，
`ValidateStage1` 会拒绝「同时要求同组两个事实」的片段或评分规则。

### 6.2 回信片段 `fragments`

`kind`：`key`（关键定制）→ `combination`（组合）→ `single`（单效果）→ `generic`（通用兜底）。
选择规则（本包声明）：`requiresFacts` 全满足、`excludesFacts` 未命中才入选；`overrides` 覆盖指定片段；
`exclusiveGroup` 同组只保留 priority 最高、其次 id 最小者；同档按 priority 降序、id 升序；
base 片段总是包含。**重要事实必须有片段 `coversFacts` 覆盖**，否则发货时报 `CONTENT_UNCOVERED`。

绑定值：`bindings.<占位名> = { source, path }`，`{{占位名}}` 必须与 `text` 一致、且都有声明。
本包唯一的绑定是 `frag_pa_forget_song` 的 `{{songTitle}}` ← `world.npcs.npc_passerby_a.memories.mem_mother.songTitle`（`摇橹调`）；
来源缺失时报 `FILL_SOURCE_MISSING`，不得编造。

D 的组合片段 `frag_pa_dream_unclear` 明确 `overrides` 覆盖 B 的「认出母亲」与 C 的「想不起歌」片段，
避免出现「认出了母亲并详述梦境」与「无法识别梦中人」并存。

### 6.3 模板与评分

```lua
FollowupTemplate = { id, letterId, opening, closing,
    baseFragmentIds, fragmentIds, fallbackFragmentIds }
RatingRule = { id, ratingSetId, priority, stars, requiresFacts, excludesFacts, feedback }
```

- 渲染：`opening` → base 片段 → 条件匹配片段 → `closing`；直接回信加载与重开不重算、不重掷。
- 评分顺序：**三星 → 二星 → 一星**；同星级内 priority 降序、id 升序。
  低星规则即使 priority 更高也不能压过高星。合规订单未命中高星时落到一星兜底（`r1_fallback`），
  **不能出现合规却没有评价**；评分缺失或没有合法规则覆盖才报 `RATING_UNCOVERED`。
- 反馈句要能追溯到事实；本包 A/G=三星、B=三星、C=二星、D=一星，同单报酬一律 80。
- 首单评分集必须同时有一、二、三星规则（`ValidateStage1` 检查），否则 A19 走查不成立。

### 6.4 首单投料 → 后果速查（由当前配置算术推算，已用独立脚本复算）

| 样例 | 投料（主 = 睡觉，除 F） | 标签权重 | 时长/延迟 | 判定 | 事实 | 片段 | 星级 |
|---|---|---|---|---|---|---|---|

## 7. 校验与自查步骤

改完内容后按顺序自查：

1. `Data.Load()` 输出 `[Data] 校验通过：…`，无错误列表。
2. `Data.ValidateStage1()` 输出 `[Data] 首单包校验通过：…`。
3. 用（本地保留的）复算脚本重算 A~G：标签、分级、时长、判定、事实、片段、评分与 `sampleCases` 声明一致。
4. 新增信件 / 词条时（A12/A13 现场验证）：只改 `data/`，不改任何 `systems/` 代码。

`ValidateStage1` 检查项摘要：C1 版本/金币/四料齐全与类型/空附件/初始设备一致/错误样例；
C2 策略布尔、profile 结构与映射、残留表连续非增、样例结构/槽位/主词 profile/A~F 齐全/同主词不同原料 ≥3；
C3 人物初态与类型、记忆对象引用、事实规则结构、互斥、片段覆盖与占位符、模板无孤儿、评分三星齐全。

程序侧注意：`Load` 失败时**不能**以默认成功继续（B1 P2）；`ValidateStage1` 失败时阻止开局或受影响操作，
显示具体路径。两者都不把「标签通过」的局部结果当成整单可发货。
