## 3. T1：修复卢卡的三条排除规则

**主改文件：** `scripts/data/ordinary_orders.lua`；必要时维护 `recipes.lua` 的预期说明及既有内容版本字段。复用原 ID，新增拆分规则使用唯一 ID。

### T1.1 两条遗忘分支

- `rule_n01_missed_promise_unaware`、`rule_n01_hurt_customer_noticed` 的 when 已要求 forget ≥ 0.6。
- 两条 unless 都只保留 recall ≥ 0.6，删掉重复的 forget 排除条件。已有接口规定 unless 任一满足即排除，所以原写法会把两条规则永久排除。

### T1.2 强镇静与记忆冲突

`rule_n01_action_dulled` 的意图：steady ≥ 0.8、calm ≥ 2.2 时出现回应迟缓；但 recall 与 forget 都 ≥ 0.6 时由记忆冲突结果承担。现有条件语言没有嵌套 OR，建议拆成以下两条互斥规则：

| 规则 | 全部 when 条件 | 产生的事实 |
|---|---|---|
| 原 action_dulled ID | steady ≥ 0.8；calm ≥ 2.2；recall < 0.6 | 保留原 action_dulled 事实定义 |
| 新唯一规则 ID | steady ≥ 0.8；calm ≥ 2.2；recall ≥ 0.6；forget < 0.6 | 同一事实定义，与上条互斥 |

严格小于使用现有 `lte`＋`ne` 两个条件，不能新造 `lt` 运算符。两条事实的 id/subject/value/important 必须一致；删除原错误的双项 unless。条件不会同时成立，不能重复生成事实或相互冲突。

### T1.3 边界验收和交接

| steady/calm 已达标时的条件 | 应有结果 |
|---|---|
| recall < 0.6，forget 任意 | 强镇静事实出现一次 |
| recall ≥ 0.6，forget < 0.6 | 强镇静事实出现一次 |
| recall ≥ 0.6，forget ≥ 0.6 | 记忆冲突事实，不能再出强镇静事实 |
