## 看故事怎么走

当前依据是用户复核修订的v06及同日M01订单化修订：8场共同前段（M01～M05五场单愿望、M06～M08三场信息）、10个二选一场景、75条订单后续、4份固定案件结局草稿，共104节点、163连接、8种模板。M01《冬衣》来信正文已确认，三档后续使用同一正文模板替换关键句段，均已定稿；明示心愿补句仍待确认。M02《空椅子》来信与模板三档后续已定稿，见[定稿文档](../../docs/文案/主线/M02_空椅子_来信与模板后续定稿_v01.md)。唯一归案序列为C01-A → C02-B → C03-A → C04-A → C05-B → C06-A；每瓶三档共用出口，低星保留真实隐私、关系与生活损失。偏离主干不再补救回归。

案件结果到达即揭晓，之后按既有顺序连续完成剩余普通订单，再判身份。没有旧第16～18轮的强制返还、救助与组合尾声。编排层仅决定图布局，不能当作游戏轮数或日历；F04按入口使用先前已公告的早船或末班船。票期、经济与最终日程尚未校准，Lua运行游戏未接入。

画布从上往下读时间，同一层横向摆不同剧情。实线箭头都是实际后续，不把目录父子关系画成剧情。默认只显示场景，把轮内药效结果压缩为箭头；**展开本轮药效后续**显示选中编排层的具体结果，其他编排层仍保留场景骨架。

- 左侧按事件编排导航；点具体场景定位。右侧打开完整内容，**收起**可腾出画布。窄窗口通过“章节／日程”和“节点内容”打开抽屉。
- **回开端**定位起点，**全图**缩小看完整路线。滚轮或加减号缩放，拖空白平移，拖节点调整位置。
- **突出此路**沿真实连接突出选中场景的前情与可达后续；其余路线淡化。全图或回开端清除突出。
- **从此处试走**开始逐步查看。右侧每条出口有“沿此路试走”；退一步可换走另一条支路，退出恢复普通浏览。试走不执行游戏条件、不自动取得证据；带条件的出口由作者核对。

建议从C01开始试走。六次沿正确选瓶序列，无论各单星级都进入“克莱拉归案”；C01-B进入F01后选A，可提前读到“吕西安的拘捕令”，不等其他主干层走完。四份结局都有“剩余普通订单”出口。无名旅人画在特殊出口区以便看全，实际是有效票期内的主动离场。
## 编辑节点与模板

节点字段：标题、类型、作者状态、轮次、轮内步骤、模板、前情、梗概、可选瓶子、触发条件、保留事实、讨论备注。

模板库复用“前情→人物困境→两份互斥愿望→实现一份与丢弃一份→药效结果及未选缺口→后续新事件”的结构。选择模板可以查看对应结构，不自动覆盖已写梗概。具体变化写在前情与节点梗概中；模板库本身由JSON统一维护，Codex可以编辑。数值、药效阈值及其余场景完整正文尚未编写；M01/M02正文已有定稿。

“＋后续节点”同时添加节点与真实箭头；修改轮次/步骤可将它放进相应层。路线箭头必须向后推进。连接已有后续时填目标、说明与条件；可以跳转、修改或删除。当前路线节点平铺管理，删除只移除该节点及相关连接，不连带删除下游独立场景。复制、删除与编辑均可撤销。旧目录稿导入时仍支持原来的树形操作。

修改自动保存；Ctrl+S立即保存。撤销/重做最多100步。输入框内Ctrl+Z保留文本原生撤销，画布上可用Ctrl+Z/Ctrl+Shift+Z撤销图修改。导出JSON可以恢复全图；导入先校验，旧文件在每次成功保存前备份。

## 用户和 Codex 共用的数据

当前图是[主线故事图_v01.json](../../docs/文案/主线/主线故事图_v01.json)，保留文件名以复用已打开的编辑器。旧图快照为[主线故事图_章节稿_v01.json](../../docs/文案/主线/主线故事图_章节稿_v01.json)。最新说明见[唯一抓凶路线与提前结局 v06](../../docs/文案/主线/主线唯一抓凶路线与提前结局重构_v06.md)；[v05](../../docs/文案/主线/主线愿望结果与收尾梗概_v05.md)保留历史，[互斥愿望与回溯 v04](../../docs/文案/主线/主线互斥愿望与回溯契约_v04.md)保留丢弃和存档规则，[v03](../../docs/文案/主线/主线路线逻辑与信息揭示_v03.md)和[路线梗概 v02](../../docs/文案/主线/主线路线框架与流程梗概_v02.md)保留历史来源。本轮不改普通订单定稿，也不接入游戏运行剧情。

- `GET /api/project` → `{project, revision, token}`。
- `POST /api/project` → 请求头 `X-Editor-Token` 为本次GET取得的令牌，正文 `{project, revision}`。
- `GET /api/health` → 应用名与实际项目路径。

Codex先读取最新图，修改指定字段，再带版本写回；不要打印令牌或存入仓库。版本过期返回409，不覆盖文件。浏览器约1.8秒同步外部修改；有未保存草稿时停止保存，提供下载草稿和载入最新版本。网络断开也保留草稿。外部同步清空撤销历史，避免撤销他人的修改。

每次不同内容的成功保存，将旧JSON备份到 `.story-backups/`；备份目录不提交。一个项目最多2500节点、6000连接、12MB；只监听本机，校验来源、令牌及同项目单服务锁。

## 互斥愿望与自动试走存档

两份愿望只实现一份，另一份丢回海里，不延期、不重发、不补做。右侧“未选愿望的后果”分别写两方缺口；出口标明实现A/丢弃B或相反。未选方不寄回信，后果只由后续实际见闻揭示。新事件中同一人物的新愿望必须明确区别。

每步试走同步保存到当前浏览器本机存储，刷新恢复当前位置。选择前检查点可回到任意已经走过的二选一；换路重新计算已选和已丢弃集合，旧路线保留为独立历史，可通过“恢复历史路线”查看（最多100条）。退出试走不删除存档；导出试走存档可备份JSON。浏览器清理本机数据会丢失这些记录。图版本变化会阻止沿旧记录继续，重新开始时保留上一版本记录，不跨版本合并。图的修改撤销与路线回溯互相独立。

这是作者试走的自动记录，不执行自然语言条件或配药规则；正式Lua游戏的日程、库存、资金、记忆、随机状态等完整自动存档尚未接入，字段和时点已列入v04契约。

`rebuild_v06.py`将用户修订文档解析为独立候选；`--apply`只用于这次已完成的迁移，通过Store版本校验和自动备份保存。已迁移后会拒绝再次执行，避免覆盖后续手动修改。当前图是继续编辑的依据。
