四原料的 ID 和顺序核对 ingredients.lua，从左到右为海盐、夜露、灰烬草、干花瓣。容器只是视觉载体；拥有数量与可用态不能由瓶中看起来装满推定。点选或拖入调用 model.Drop("ingredient", ingredientId)，每次一份；移出走 model.TakeOut("ingredient", ingredientId)。词卡对应 Drop/TakeOut("word", tokenId)，不能把 wordId 当来源实例。

当前旧锅设备上限为 1 主词、2 辅词、2 原料；底部中央大牌为主词，两边小牌为辅词，下方整条为原料摘要。四个原料源不表示四个投料槽；圆形装饰已去掉，避免误解为额外槽位。未来设备扩展不能受这三张烘焙牌框限制，需动态模板重排。

此图展示双面板展开且锅口/四原料可见。构图实际左板约 28%、右书约 32%，不是严格的 24/50/26 网格；C 需按手机可用尺寸重新确定面板宽度和触点，不能据静态图宣布通过。左栏三个分类页签、四卡片和右书三个书签都只是重复控件样式，不硬编码类别/故事总数。

药炉保持纤巧支架与双环把手，可见药液、草药与炉火，无常驻蒸汽；锅中草药是装饰性熬制状态，不展示玩家配方的精确原料。pending 后禁止换料，主按钮仅恢复当前结果；完整后续与星级之后再选择 Resolve(false) / Resolve(true)。侧栏、历史、返回和关闭都不得隐式结算。

后续拆层建议：室内底图/桌布 → 原料架 → 四原料及动态数量牌 → 炉体/炉火 → 左词条板及可复用卡片 → 右记录书及书签 → 订单、选择摘要与按钮 → 程序文字。必须补出无侧栏背景，支持收起/恢复；书页、卡片和原料状态不可只交整页 PNG。
