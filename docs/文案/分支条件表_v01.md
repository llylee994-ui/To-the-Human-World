# 分支条件表 v01（N01–N10）

> 2026-10-08 · 数值层第一张表。用途：把每单的**发货门槛**与**星级分区**写成能核对、能回填配置的一览。
> **基线**：N01–N10 每封五支已全部定稿（50／50，首单埃利亚斯八版另算）——本表按**最终分支正文**逐支对应属性，不再有"待补正文"。数字全部为草案，经《数值验算报告》与组长确认后定稿。
> 与代码对应：要求栏＝`requirement`（`tags` 最低权重／`conditions` 时效与上限／`forbiddenEffects` 硬零）；分支＝`orderRatings` 评分规则（事实→星级），判星取命中里**星级最高**，一条都不命中会抛 `RATING_UNCOVERED`——所以每单条件必须构成**完整分区、三星兜底**。

## 1. 先行约定（v1，待数值验算复核）

- 主轴达线：**0.8**（发货门槛），样例 1.0；备用路径允许 1.5。
- 主导键达线：**0.6**。
- 词条：主属性 1.0＋尾值 ≤0.2（2～3 个）；**同一属性尾值最多出现在两张词上**（防 3×0.2＝0.6 误触主导键）。
- 硬零禁止（`forbiddenEffects`）：涉及的属性不得出现在可用词条的尾值里；做不到就改判"≤上限"。
- 时效：沿用各单现拟稿（起效 ≤1 小时、持续 2～4 小时、个别单 sleep ≤0.4 等），逐单登记为待审。

## 2. 排布方法（2026-10-08）

- 三星兜底（各主导键均未过线，其余一概不管）；**二星两支各挂一个主导键**（A、B）；**一星两支**＝其一"C 独立行"（吸收**全部** C≥阈 情形），其二"A＋B 组合"。
- 若设第三键 C：C 行吸收全部 C≥阈 情形，**其余各行统一加 `C < 阈`**（否则 C 高时会被二星行抢走或漏接）。
- 键必须**从分支事实长出来**（先读定稿正文再定键，不先定属性改正文）；键的字面必须能从本信或先前信件剪出来，剪词阶段逐键预检。
- 分区自查逐格核对（键全组合），不许留空格；检查脚本的边界样例随键位扩表。

## 5. 展开顺序

1. 组长确认第 2 节方法与第 3 节样板（N10）。
2. 助手按样板逐单起草键位与条件（每单同款一表，含依据与分区自查）→ 逐单报组长确认。
3. 与[词条数值表](词条数值表_v01.md)联动做字面预检、与[供给验算表](供给验算表_v01.md)联动做来源预检。
4. 全部键位定死后跑《数值验算报告》，再回填各封作者区与配置 data。
