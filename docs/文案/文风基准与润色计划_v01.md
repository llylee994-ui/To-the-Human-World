## 0. 世界观框架与信件形态（2026-10-03 组长修正，先于一切正文改写）

写任何一封之前先对齐本节；与本节冲突的旧稿写法（含已落盘文本）一律作废、按待重写处理。

1. **铺子在人间之外**；人间不知道魔药铺的存在，人间的信里也不出现它。
2. **信不是写给店主的**：人物的念头自己汇聚成文字，像日记一样落进海里，被玩家打捞上来。信里没有收信人，也没有向任何人提出的请求。
3. **信件固定三段**：
   - **自我介绍**：人物用**自己的口吻**说清自己是谁（名字、年纪、营生、住处），不再是第三人称档案段；
   - **正文**：处境、念头、想做还没做的事；
   - **落款**：姓名＋地址（纯地址，不带“后门收”“不经总收件台”这类投递说明）。
4. **写作禁令**：不得出现“店主：”“海边的店主”“请你／你能不能让我……”“请让我……”“听人说海边的魔药铺能帮人实现愿望”“谢谢你看完”“地址写在下面了”“才写的信”这类称呼、请求与投递句；信不解释自己如何到达玩家手里。
5. **口吻卡同步**：第 3 节已将旧“称呼店主”栏替换为气口提示；同一人物跨信保持一致的是嗓子。
6. **现状**：旧信件（含运行文本 `letters.lua` 首单、`ordinary_orders.lua` N01/N02、`followup.lua` 片段）按新框架待重写；已逐篇确认的新稿以各自定稿状态为准。开场与埃利亚斯首封来信、其七版直接后续和 N02 诺拉来信已正式定稿；其余回信与关联变体仍待重写，具体完成要求待定。运行文本暂保留旧版，不把旧版当新正文的约束。

7. **叙事与交接分开**：人间人物的念头不解释词条、药效数值、可剪权限、槽位、确认、重置、星级或分支。只写当下能知道的事，不暗示尚未发生的后果、凶手身份或结局资格。必要机制说明留在要求栏、作者契约与程序交接中。
8. **真实人间文书另辨**：旧求助记录、收条、契据和证词可以保留其真实收件人及人间用途，不能把写给维尔的历史求助也改成无收件人的念头。上一任店主便笺与终局特殊瓶沿用各自演出身份，不套普通人间来信格式。

## 1. 现状判断

现有正文的问题不在于"辞藻不够"，而在于**不像人写的**：

1. **所有人在同一个嗓子里说话。** 11 岁的孤儿、46 岁的港商、70 岁的老船匠，句长、修辞、礼貌程度几乎一样，分不出谁是谁。
2. **每句都在完成任务。** 信被"可剪词"和"要点"牵着走，句子排得整整齐齐，没有寒暄、跑题、改口、写坏了一行再补一句。
3. **把潜台词说尽。** 好的意象（"像不肯承认节庆结束"）成立之后，总要再补一句解释，读者没地方站。
4. **回信像总结陈词。** 大量"今天总算……""今天没有躲……"，每个人都给自己写一句道德小结。
5. **对仗癖。** "既不……也不……""不 A，只 B"的工整结构反复出现，是文案体，不是人话。
6. **词汇太现代、太行政。** 登记、核对、交接、说明、接收人、处理——灰港是个港口市镇，该用账房、签条、凭据、门房、值夜、短工、煤牌、冬济这类词（克莱拉是唯一例外，见口吻卡）。
7. **词被"摆"在重音上。** "我需要{{勇敢}}一点""我想重新有一点{{快乐}}"——句子首先是词条托架，其次才是话。

改法不是加形容词，而是**给每个人一个嗓子、给每封信一点生活**。

## 2. 文风基准（R1～R11）

- **R1 一人一嗓**：按第 3 节的口吻卡写。句长、用词域、在意什么、回避什么，全按人物来；人间人物不称呼店主。
- **R2 少总结、多动作**：回信结尾不写"今天总算……"，改成一个具体动作、一个没说完的话或一件小事。宁短勿满。
- **R3 允许不完美**：断句、重复、改口（"我本来不想写下来，想想还是写了"）、跑一句题再收回来。人物不是演说家。
- **R4 时代词汇表**：优先用账房、签条、凭据、门房、跑腿、递话、值夜、短工、粗布、煤牌、冬济、潮水、栈桥；慎用登记、核对、交接、说明、接收、处理、流程。
- **R5 全部正文先写完**：先完成剧情与每封信（含回信），写作阶段不标 `{{词}}`，不保留旧词字面或旧标记位置。全部正文审定后，再讨论剪哪些字、剪几处，最后配属性与数值并对齐交接与检查。属性覆盖是事后校验，不能先定词再造句。
- **R6 事实与结构守约**：按第 4 节保护案情、人物关系、ID 和分支事实；旧正文与旧剪词的字面不是写作硬约束。
- **R7 篇幅**：正文可增 0～30%，回信可缩。回信以"像一个人写的条子"为准。
- **R8 连句成气，减少不必要的停顿**：用户在开场试写后明确要求“少一点逗号”“句号也少一点，不要句号代替逗号”，并确认修订稿。先理顺语序、合并重复铺垫，让意思自然连贯；不要机械删标点、堆成长句或把逗号换成句号。破折号一篇信里最多一处、能不用就不用。短促只在情绪或场景需要时偶尔使用。判据：读出声自然顺畅，不像逐条念信息；标点节奏参考[开场与首封来信定稿](开场与首封来信_定稿_v01.md)。
- **R9 语气随人、随情境**：允许“呢、吧、啊、呀、嘛、唉”等语气词，放在迟疑、埋怨、试探、改口或宽慰的气口上，不按句数添加，不让所有角色同样口语化。老人可以念叨，孩子可以较劲，克莱拉的圆话仍有分寸。
- **R10 不解释功能，不预告后果**：禁止借人物说“这只影响我的记忆”“不会改变别人的想法”“还能做事，不会犯困”等系统边界，也不写“这样便能交出证据／修复关系／得到认可”的分支提示。人物可以写自己的不适、安排与担忧，但须从生活处境自然说起。已经发生的回信写具体经过，不复述药效清单，不作满意度总结。幽默从现场长出来，不要求每段都讲笑话或收一句金句。
- **R11 核心心愿加粗**：每封来信须用人物自己的话说清最想做到的事，并将表达核心心愿的完整句子加粗，方便玩家理解。表达平铺直叙、自然流畅，不让玩家猜省略的动作或隐喻；不为突出心愿加入求药、规则或分支剧透。必要的关键背景句可少量加粗，避免整段加粗。加粗是阅读提示，不代表可剪词、药效标签或交付门槛；具体完成要求在独立要求栏另行审定。定稿时同时确认并保留加粗位置。**加粗不可剪（2026-10-04 组长裁决）**：加粗区间内不设 `{{}}` 可剪位置，剪词只在非加粗文字里找字，检查脚本对这一条直接断言。它只约束剪词阶段，不反向约束写作：加粗位置仍按本节从心愿与关键背景出发，不为了给词留地方而回避加粗。
- **R12 不写成套短语（2026-10-05 组长裁决）**："从头……到尾"一类固定框架一律不用（"从头到尾""从头吃到尾""从头唱到尾"……）。要表达"完整走完、一路做到底"，落在具体动作或具体状态上（例如把结果写实："碗底刮得干干净净"）。机械检查已按此拦截（`BANNED_FRAMES`，命中即报"禁用"）。

## 4. 写作边界与配置交接约束

**写作阶段**：新正文不受旧剪词字面、数量或顺序限制；旧稿里的称呼、投递说明、功能解释和说理结尾可以重写。不得把旧脚本对标记的校验反过来当写作提纲。以下结构与事实仍保留：

1. 全部正文定稿后再确定剪词，来源表与校验随新剪词一起更新；当前运行数据中的旧标记保留现状，不在本轮改动。
2. 表格与 ID：`nXX_result_N` 三行结构、"全文 variant `nXX_rN_base`"、60 行记忆选择表、趣味门禁表、来源表。
3. 14 条 faded 记忆变体的**首行**必须含"说不全"或"接不全"。
4. 旧要求栏的行文格式（如 `S主勇敢三星`、`三星S+辅X`）、数值与禁止效果保留供配置核对；正文定稿不自动确认这些条件。N02 新稿的具体完成要求已明确待定，不直接沿用旧参数，也不在本轮改动运行配置。
5. 附件 ID（`att_*`）、作者证据边界及评分依据所表达的事实；不能把这些内部说明塞进人物正文。
6. 人物身份、住处、关系与主线 `### M0X｜标题 · letter_mXX · 人物订单` 式标题。纯地址保留真实地点，删除“后门收／转交／敲三下”等投递指令；代笔设定暂保留为人物关系资料，不在念头正文里解释写信手续，其最终呈现待另定。
7. 星级语义：3/2/1 各自的事实条件与"本人已见"口径。
8. 时代口径：不出现现代行政/科技词（克莱拉的口吻卡例外，且仍限旧式文书语）。

**配置交接阶段**：正文与剪词审定之后再同步 data、来源账与检查。已保存信件位置或回信解释变化须按内容版本处理；不得静默覆盖旧存档。这个阶段另行授权，不在当前 docs 改稿中执行。

## 6. 每批流程与版本处理

1. 改稿：按口吻卡 + R1～R11，先读完该封契约，分批写完全部剧情与信件。当前正文不标剪词、不配属性，不借人物解释功能或预告分支。
2. 写作自检：朗读检查连句、语气与人物差异，核对案情及该分支已发生事实，确认核心心愿清楚且已加粗；逐篇登记正文及加粗的定稿状态，具体完成要求单独登记。全部正文审定后才讨论剪词与属性。
3. 交接检查：确定剪词后同步来源表，跑 `python -X utf8 docs/验证/check_delivery_content.py`；涉及运行 data 时再跑预算与单次性检查。当前文档同步可以检查旧交付结构，但通过旧检查不表示新文风已定稿。
4. 冻结基线：`check_single_use_content.py` 的十个冻结文件与 stage1 基线锚在 `8589b0a`；批次 C/E 改到 `ordinary_orders.lua`、`letters.lua` 时，把基线整体前移到本批提交并注记原因（不再逐处放宽）。
5. 版本：当前运行版已是 `story-v0.4-r1`；后续回填若改变已保存信件或回信的解释，应递增到新的 `contentVersion` 并在填写说明登记，不能复用此版号。当前 docs 试写不升运行版本；`synthesisVersion` 与存档 schema 不动。
6. 记录：每批一条行动记录，列明改了哪些信、跑了什么检查、哪些没改（如纯作者说明段）。

## 7. 历史试点：改前 → 改后（不作现行定稿）

以下保留旧修订过程。其中“借你的勇敢”等求药句违反第 0 节，“木头不会说谎，纸会”等金句已被退回；新写作不得照抄。当前文风参考以[诺拉来信定稿](普通订单/N02_两个人的晚饭_来信定稿_v01.md)为准，包含已确认的加粗位置。

**M05 吕西安**（港商；账目、门槛、门房）

> 改前：他们明天来数箱子，我想能站在仓库门口，不再每听见一个数字就往别处看。……我需要{{勇敢}}一点，亲自面对，别再叫门房替我挨问。我的工人很{{累}}，总归不能让他们连今天的箱子也数两遍。
>
> 改后：他们明天来数箱子。账上写着一百，地上只有七十六。木头不会说谎，纸会。……少掉的二十四箱，已经有人替我背过。我的门房上周替我把"不清楚"答了三遍，答到嗓子哑。这回我想自己站到门口，问一句答一句。借你的{{勇敢}}使一次，用完就还账，不拿它撑门面。只一条：我的工人很{{累}}。扛了一天的包，别再让他们陪我把箱子点第二遍。

改动要点：数字提前当"人物语言"用；把"我需要勇敢一点"这类托架句换成他自己的话说"借来使一次"；门房从抽象责任变成一个答到嗓子哑的人。

**N04 奥托**（11 岁，口述由皮特代笔）

> 改前：店主，皮特替我写，最后那句不是他加的。节庆散了，钟楼又只有灰尘，我有些{{难过}}。……我想重新有一点{{快乐}}，下工后和他把纸做的旗子收好。旗子总粘在扫帚上，像不肯承认节庆结束。
>
> 改后：皮特替我写。最后那句话不是他加的，是我说的。节庆散了，钟楼又只剩下灰。我扫得很没劲，{{难过}}。……我想再{{快乐}}一点，不用很多，够我把旗子收好就行。纸旗子在楼梯扶手上挂了一整个节期，取下来的时候粘在扫帚上，甩了三下才掉。它好像不肯承认节庆完了。我也不肯。

改动要点：孩子不写"我有些难过"，写"我扫得很没劲"；"甩了三下才掉"这种具体动作代替抽象形容；保留"最后那句不是他加的"这个好设计，仅把口气改成口述感。
