# 词条设计｜从人物生活里剪下词

> 2026-10-03 · v0.2 配置说明。回应组长反馈：前一批过度重复勇敢、安静、累等词，两个订单的组合体验相似。
> 本稿的八个生活词及 30 词池已获授权落盘；详见[配置交接](配置交接_v03.md)。原首单 A～G 预期保留，内容版本已升级。

## 1. 本次修订

两单各交四个新词，正文不再重复标出勇敢、安静、累、忘记、快乐和睡觉。旧词仍可从已收到且已读的其他信件剪下；r3中仅未消耗的来源卡可跨订单投入；不是删除旧词，也不是每单必须凑出独立完美配方。

| 订单 | 新可剪词 | 语义方向 |
|---|---|---|
| N01 卢卡 | 面包、答应、抬头、手稳 | 物件、关系、行为、身体 |
| N02 诺拉 | 回家、笑、汤、等 | 关系、行为、物件、时间 |

每个词必须在信里有具体含义，不能为了充词库突然塞一句「我需要勇敢、快乐、记忆和时间」。词条显示文本与底层药效标签分开：读信时获得人物语言，熬药时能查看它实际携带的药效，不让玩家只凭意境盲猜。

## 2. 新词交接表

以下八词的 ID、权重、分类已配置，所有正式词均有主词 profile，r3均为一次性。Potion／Order已实现，完整确认保存仍待本机联调，见[一次性内容交接](一次性词条_内容交接_r3.md)。

| 词 / 建议 ID | 类别 | 药效提案 | 与其他词的区别 |
|---|---|---|---|
| 面包 / `word_bread` | 物件类 | appetite 1.0 | 唤起进食欲望，不凭空变出面包；与汤共用食欲标签，来源与文本用途不同 |
| 答应 / `word_promise` | 关系类 | recall 1.0 | 让本单已声明的承诺更清楚；不强迫别人履约，不让口头承诺变成法术契约 |
| 抬头 / `word_lookup` | 行为类 | brave 1.0 | 从面对他人的动作引出勇气；是现有勇气标签的具体表达，不伪称新系统 |
| 手稳 / `word_steady_hands` | 身体类 | steady 1.0（新标签） | 身体不再抖、拿放更稳；不自动镇静、壮胆、提升识字或计算能力 |
| 回家 / `word_homecoming` | 关系类 | recall 0.6 + dream 0.4 | 唤起已声明的家中记忆，并影响自然入睡后的梦；不传送、不召回别人、不提供陌生地址 |
| 笑 / `word_smile` | 行为类 | happy 1.0 | 愉悦通过行为词表达；不保证关系修复或所有人满意 |
| 汤 / `word_soup` | 物件类 | appetite 1.0 | 进食欲望；不生成食物，不给食物无条件治疗能力 |
| 等 / `word_wait` | 时间类 | calm 1.0 | 降低急切、愿意等待；不改变世界时间、票期、船期或药效时长 |

这里的多样性有三种层次：不同人物语言承载同一作用；一个词同时携带多个已有作用；少量明确的新作用。八个词不意味着八个新系统。不要把每个名词都做成独立例外，也不要把所有新词都翻译成镇静。

语义类别用于词条整理和无名者资格，药效标签用于合成；它们不是同一张分类表。物件类与时间类是新增类别提案，须同正式词池一起冻结，不能通过改类别刷身份门槛。

## 3. 两单的实际差异

N01 主要求由镇静改成「手不再发抖」。只让手稳，他仍可能紧张，却能递好袋子；加抬头让他说话更大胆，既可能越界，也可能完成道歉；加答应让旧承诺更清楚；加入别的信剪来的遗忘，仍可能忘掉补偿。稳手与镇静因此有不同作用。

N02 继续要求心情轻快，但从笑、汤和回家的生活语义出发。加汤让母亲也坐下来吃；加等让她愿意听完；加回家让已知的家庭片段更清楚，不把儿子强制留在本地。已有遗忘与勇气仍能从别单带入，但不再充当本信剪词的主体。

## 4. 记忆与组合的边界提案

新词涉及 recall，当前普通包需补清楚恢复与互斥，不能继续宣称「本包没有任何可达 recall 来源」。

- N01 的 recall 与 forget 都只作用于 `mem_market_mistake`，含当时的承诺；最终 recall ≥ 0.6 且 forget < 0.6 时，相关经历更清楚。
- N02 的 recall 作用于另一个初始明确存在的 `mem_home_table`（儿子小时候在门口等汤的记忆），forget 仍只淡化 `mem_last_argument`。可以记起幼时的饭桌却忘掉两年前的承诺，不是人物全局失忆。
- 同一记忆对象同时命中 recall ≥ 0.6 与 forget ≥ 0.6 时，本稿采用「记忆片段交替浮现，无法稳定使用」的单独组合事实；不输出既完整履约又完全忘记的两份矛盾回信。具体阈值待审与配置复算，不在此改变全局合成算法。
- 回忆在本批仅强化初始已存在的记忆，不恢复其他订单已经确认丢失的过去；恢复旧记忆是另一项功能需求，不能暗中附带。

## 5. 程序交接范围

需要新增 steady 标签与订单阈值查询、新词定义和主词 profile、新语义类别、recall 事实与组合片段覆盖。合成仍以少量标签求值，不按每个词写特殊配方表。所有这类变更需由内容与程序确认后接入，不修改阶段 1 首单来迁就新稿。

原两单 A～D 的叙事骨架保留，但新词与稳手主轴已经使旧稿「可以按现有八词直接复算」的说法失效。普通包中同步撤下该结论，标出新版待联调样例。

词池账面种类增加不能证明无名者达标；仍需实际投放、类别冻结、可用词留存及当前分支可达性验证。
