## 一、这个项目是什么

《寄往人间》—— TapTap 游戏比赛参赛作品，用 **TapTap Maker（UrhoX 引擎 / Lua）** 开发，
目标平台是**移动端竖屏**（设计分辨率 1080×1920）。

玩法核心：玩家在海边魔药铺打捞漂流瓶、读信、从信中剪下词条、炼制药水寄回人间，
在满足陌生人愿望的过程中逐渐拼出一桩谋杀案的真相与自己身份的谜题。

设计文档在 `docs/`，**动手前请先读** `docs/寄往人间_开发计划与验收标准.md`
（阶段划分、每阶段验收标准、取舍原则都在里面）。

## 二、装环境（不需要 git）

本地预览**不依赖 git**，已确认过：Maker 的预览只检查项目里有没有
`.maker-mcp/config.json`（本包里已带），整个预览流程不调用 git。

步骤：

1. **装 Node.js**（需要 `npx`）。没有 Node 的话去 https://nodejs.org 下 LTS 版。
2. **装 Maker 工具链**，在终端执行：
   ```bash
   npx -y @taptap/maker install --ide codex,cursor,claude
   ```
   这会装好 Maker MCP、CLI 和本地运行时的管理工具。装完重启你的 AI 客户端。
3. **解压本包**，得到一个包含 `scripts/`、`docs/`、`assets/` 的工程目录。注意解压后
   确认 `.maker-mcp/` 这个隐藏目录在（有些解压工具会跳过点开头的目录）。
4. **装本地运行时**（首次约 35MB）：
   ```bash
   taptap-maker preview install --target-dir "<工程绝对路径>"
   ```
5. **起窗口看效果**：
   ```bash
   taptap-maker preview start --target-dir "<工程绝对路径>"
   ```
   窗口是竖屏 1080×1920。启动日志里会打印阶段 0 的自检结果，应该看到
   `通过 12，失败 0`。

**git 只影响两件事**：一是从 GitHub 同步代码，二是`提交构建`（Maker 的远端构建需要 git）。
所以日常开发和本地预览不需要 git；要发布或从仓库拉更新时，得装 git 或者让另一位同学
在你这边跑构建。Git for Windows 是个很小的安装包，建议有空就装上。

## 三、两个已经踩过的坑（省你时间）

**1. `UI.Init` 必须显式指定字体，否则整屏不渲染。**

`default-dark` 主题默认加载 `Fonts/NotoSansSC-Regular.ttf`，但运行时实际只带
`Fonts/MiSans-Regular.ttf`。字体加载失败的表现不是"文字不显示"，而是**整个 UI 全不画**，
你会以为逻辑没跑起来，其实逻辑全对。`scripts/main.lua` 的 `InitUI()` 里已经显式指定了
MiSans，**新增界面时不要改回主题默认字体**。

**2. 纯 UI 项目没法用无头截图做视觉验收。**

`-screenshot` 抓到的是纯白图，Maker 预览也报告 `screenshots_supported: false`。
判断渲染是否正常，只能靠 `Widget:GetComputedSize()` 查布局尺寸（`debug/SelfTest.lua` 里有
现成的 `CheckUILayout`），或者自己看窗口。

## 四、代码与内容的边界（重要）

这条路是两个人并行开发的唯一接口，务必遵守：

| 谁 | 只改这些 |
|---|---|
| 开发（你） | `scripts/` |
| 文案（另一位） | `data/`、`docs/` |

**不要互相覆盖对方的文件。** 所有剧情、人物、信件、配方数值都在 `data/`，
系统只读不写死剧情——这是设计文档里明确的架构原则，也是两个人能并行的前提。

`data/` 的格式已经冻结，样板在 `scripts/data/letters.lua`（路人甲那封信），
照着它的结构写就行。总入口 `scripts/data/init.lua` 的 `Data.Load()` 会做交叉校验，
配置写错会直接打印出是哪封信、哪个字段的问题，不会静默失效。

**下一步（阶段 1，核心闭环 MVP）**：接入六个系统，做出
「读信 → 剪词 → 炼药 → 发货 → 世界变化 → 后续来信」这条完整链路，
只做 1 个 NPC、2 封信、5～8 个可裁剪词。

需要补的模块：`systems/Letter.lua`、`WordToken.lua`、`Potion.lua`、`Order.lua`、
`WorldState.lua`、`Narrative.lua`，以及 `ui/` 下的打捞、读信剪词、炼药三个界面。

**两条硬约束**：

1. `Potion` 必须按 `scripts/data/synthesis.lua` 文档注释里写的**八步求值顺序**实现，
   不要自己发明算法——魔药的数值平衡由文案同学在配置里调，代码跟着配置走。
2. 炼药投料有**槽位上限**（见 `equipment.lua` 的 `slots`）：主词条 1、辅助词条 2、
   原料 2、特殊物品 1。基础原料只有 2 格而原料负责 5 个属性，玩家必须取舍——
   这是订单判定产生玩法深度的地方，不要为了方便把关卡放开。

## 六、给 AI 助手读的开发规范

工程里有完整的引擎开发资料，让你的 AI 助手**先读再写**：

- `AGENTS.md` —— 引擎开发规范入口（必读，含长度单位、脚手架、资源路径等硬规则）
- `engine-docs/lua-scripting-guide.md` —— Lua 开发指南（必读）
- `engine-docs/recipes/ui.md` —— UI 系统权威参考
- `examples/14-ui-widgets-gallery.lua` —— 全部 45 个控件示例
- `examples/15-inventory-drag-drop.lua` —— 拖拽实现（配方槽、拼贴诗要用）
- `examples/17-chat-window-rich-text.lua` —— 富文本与可点击片段（**剪词要用**）
- `urhox-libs/` —— 引擎工具库源码，**只读**，改它不会生效

**关于本包里缺的两样东西**（都不影响开发，可自行补齐）：

1. `.agents/`、`.claude/`、`.codex/`、`.cursor/`、`.gemini/` 这几个 AI 技能目录在打包时被
   排除了（它们是链接，内容是重复的）。需要的话在工程根目录执行
   `powershell -NoProfile -ExecutionPolicy Bypass -File tools/install-skills.ps1 all` 重新生成。
2. 三个 UI 框架技能自带的字体包（`ui-astroon` / `ui-brawlforge` / `ui-pixelforge` 下的
   `fonts/`，共约 51MB）被排除了——本项目用的是 `urhox-libs/UI`，与这三个框架无关。
   需要的话执行 `taptap-maker dev-kit update --target-dir "<工程绝对路径>"` 重新下载完整包。
