## 一、这个项目是什么

《寄往人间》—— TapTap 游戏比赛参赛作品，用 **TapTap Maker（UrhoX 引擎 / Lua）** 开发，
目标平台是**移动端竖屏**（设计分辨率 1080×1920）。

玩法核心：玩家在海边魔药铺打捞漂流瓶、读信、从信中剪下词条、炼制药水寄回人间，
在满足陌生人愿望的过程中逐渐拼出一桩谋杀案的真相与自己身份的谜题。

设计文档在 `docs/`，**动手前请先读** `docs/寄往人间_开发计划与验收标准.md`
（阶段划分、每阶段验收标准、取舍原则都在里面）。

## 三、装环境

### 1. 装 Node.js 与 Maker 工具链

需要 Node（用 `npx`）。然后装 Maker MCP、CLI 与本地运行时管理工具：

```bash
npx -y @taptap/maker install --ide codex,cursor,claude
```

装完重启 AI 客户端。

### 2. 克隆工程

```bash
git clone git@github.com:llylee994-ui/To-the-Human-World.git
cd To-the-Human-World
```

### 3. 处理 Maker 绑定（按你的权限情况二选一）

先看下面的情况 B 还是情况 A——**当前实际是情况 B**（项目列表里看不到这个项目）。
情况 A 是你之后被加进项目、或 owner 给了你权限时才走的路。

> 如果你之后要走情况 A，有个**顺序不能错的坑**：Maker 的绑定流程会**接管 `origin` 远端**
> （内部执行的是 `git remote set-url origin <Maker地址>`）。clone 之后 `origin` 指向 GitHub，
> 如果直接绑定，GitHub 远端就被覆盖了，之后 `git push` 会推到 Maker 去。
> 所以走情况 A 之前必须先执行 `git remote rename origin github`。
> 走情况 B 则不需要动远端，`origin` 继续指向 GitHub，正常 push 即可。

#### 情况 A：你的账号能被加进这个 Maker 项目

```bash
taptap-maker init --app-id 76909fb8-3dc3-4adc-8c49-fe56bab4393e --target-dir "<工程绝对路径>"
```

绑定完成后你的远端应该是两个：`github` 指向 GitHub（日常推送用），
`origin` 指向 Maker（构建用）。用 `git remote -v` 确认一下。

绑定同时会把 AI 开发资料（`urhox-libs/`、`engine-docs/`、`examples/`、`AGENTS.md` 等）
装到工程里。这些是本地资料，已在 `.gitignore` 里排除，不会进仓库，也不会互相覆盖。

#### 情况 B：项目列表里看不到这个项目（当前的实际做法）

**不要反复重试 `init`**——`init` 需要服务端认你的账号对这个项目的权限，看不到就绑不上，
重试也不会变。改用最小配置，这条路已经实测验证过可行：

```bash
mkdir -p .maker-mcp
```

然后新建 `.maker-mcp/config.json`，内容只有一行：

```json
{"project_id": "76909fb8-3dc3-4adc-8c49-fe56bab4393e"}
```

> 用编辑器新建这个文件最省事，别用命令行 echo，省得跟 shell 的引号转义纠缠。
> 如果你是 PowerShell：
> `New-Item -ItemType Directory -Force .maker-mcp | Out-Null` 然后
> `Set-Content .maker-mcp\config.json '{"project_id": "76909fb8-3dc3-4adc-8c49-fe56bab4393e"}' -Encoding ascii`
> （**必须是 ascii**，Windows PowerShell 的 utf8 会带 BOM，JSON 解析会失败）

**为什么这样可行**：Maker 的本地预览只做一件事——检查工程里有没有 `.maker-mcp/config.json`
并且它含 `project_id` 字段。它不校验所有权、不校验登录、不联网。实测把配置换成上面这一行
之后，预览正常启动、自检通过、正常退出。

**代价**：你不能用「提交构建」（那个动作需要真实绑定 + Maker 远端的 git 凭证），
构建和发布由项目 owner 来做。日常开发与本地预览完全不受影响。


### 4. 起窗口

```bash
taptap-maker preview install --target-dir "<工程绝对路径>"   # 首次约 35MB
taptap-maker preview start   --target-dir "<工程绝对路径>"
```

窗口是竖屏 1080×1920。启动日志里会打印阶段 0 的自检结果，应该看到 `通过 12，失败 0`。

> 关于 git 的补充说明：本地预览本身**不依赖 git**（Maker 的预览只检查项目里有没有
> `.maker-mcp/config.json`，整个流程不调用 git）。git 是给「拉取代码」和「提交构建」
> 用的。这条只是让你知道出问题时该往哪查，不是说你不需要 git。

## 四、两个已经踩过的坑（省你时间）

**1. `UI.Init` 必须显式指定字体，否则整屏不渲染。**

`default-dark` 主题默认加载 `Fonts/NotoSansSC-Regular.ttf`，但运行时实际只带
`Fonts/MiSans-Regular.ttf`。字体加载失败的表现不是"文字不显示"，而是**整个 UI 全不画**，
你会以为逻辑没跑起来，其实逻辑全对。`scripts/main.lua` 的 `InitUI()` 里已经显式指定了
MiSans，**新增界面时不要改回主题默认字体**。

**2. 纯 UI 项目没法用无头截图做视觉验收。**

`-screenshot` 抓到的是纯白图，Maker 预览也报告 `screenshots_supported: false`。
判断渲染是否正常，只能靠 `Widget:GetComputedSize()` 查布局尺寸（`debug/SelfTest.lua` 里有
现成的 `CheckUILayout`），或者自己看窗口。

## 五、代码与内容的边界（重要）

这条路是两个人并行开发的唯一接口，务必遵守：

| 谁 | 只改这些 |
|---|---|
| 开发（你） | `scripts/` |
| 文案（另一位） | `data/`、`docs/` |

**不要互相覆盖对方的文件。** 所有剧情、人物、信件、配方数值都在 `data/`，
系统只读不写死剧情——这是设计文档里明确的架构原则，也是两个人能并行的前提。

`data/` 的格式已经冻结，样板在 `scripts/data/letters.lua`（路人甲那封信），
照着它的结构写就行。总入口 `scripts/data/init.lua` 的 `Data.Load()` 会做交叉校验，
配置写错会直接打印出是哪封信、哪个字段的问题，不会静默失效。
