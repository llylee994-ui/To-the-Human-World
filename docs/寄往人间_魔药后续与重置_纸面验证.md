# 《寄往人间》魔药后续与重置：路人甲纸面验证

> 日期：2026-10-02（北京时间）
> 定位：设计讨论样例与手工推演，不是运行时测试或已通过的阶段验收。
> 对照：游戏大纲 §3.2、§6.2、§8.0、§16.1；开发计划 §1.5、A14～A18。
> 组长确认：2026-10-02 已认可 A～D 的后续样稿，以及额外药效影响私人记忆与家庭互动的表达深度；数值、配置接口与运行时行为仍需后续验证。

## 一、验证目标与边界

用同一订单比较不同合规配方，检查额外药效是否产生可辨认的生活后果、模板是否自然、组合反馈是否矛盾，以及确认 / 重置是否有明确状态边界。

本样例只涉及路人甲，与主线案件无关。不制造新案件证据，不展示多日后的连锁结局，不代表“跨订单涌现”已成立；后者需要另外验证开发计划 F3a。

## 二、现有素材与本轮假设

现有素材来自 `scripts/data/letters.lua`、`words.lua`、`ingredients.lua`、`equipment.lua`、`synthesis.lua`：

- 路人甲在码头搬货，不识字，信由面包坊伙计代写；妹妹在面包坊帮工。
- 首信要求：“希望能踏踏实实睡一晚，第二天起来还有力气干活”。文中提及母亲、梦、疲劳与想忘记的事。
- 当前订单只配置 `sleep >= 0.8`，尚未覆盖持续时间与次晨工作条件。
- 旧锅支持 1 主词条、2 辅助词条、2 原料槽；下列四种配方都不超过容量。
- 主词“睡觉”的 sleep 为 1.0；辅助权重为 0.6，同标签奖励为 0.4；“梦”携带 dream=1.0、sleep=0.4；“忘记”携带 forget=1.0；海盐只加稳定性。

本轮 A～D 暂按“药效能够覆盖睡眠且次晨不妨碍工作”比较表达差异。**这是一项纸面输入假设，不是现有配置已经证明的结果。** 基础时长、生效速度、强度与次晨工作能力的实际换算必须在阶段 1 样板中补齐。

记忆作用域也尚未配置。本轮将“与母亲有关的一小段私人记忆变得模糊”作为候选情境，用来检查模板一致性；不等于默认遗忘全部记忆，更不能把此解释直接用于所有 NPC。出现细微梦境与记忆反馈所需的最低权重仍需试玩校准。

## 三、配方与候选事件事实

| 用例 | 配方 | 按当前合成配置推算的标签 | 本轮候选直接事实 | 判定边界 |
|---|---|---|---|---|
| A | 主“睡觉”＋海盐 | sleep=1.0 | 睡眠改善，次晨工作状态恢复 | 标签达标；时长与工作条件仅按本轮假设 |
| B | 主“睡觉”＋辅“梦”＋海盐 | sleep=1.64，dream=0.6 | 睡眠改善，短暂梦到母亲，向妹妹提起梦 | 同上；梦不保证是快乐或噩梦 |
| C | 主“睡觉”＋辅“忘记”＋海盐 | sleep=1.0，forget=0.6 | 睡眠改善，某段私人记忆变淡，妹妹察觉细节缺失 | 同上；仅弱反馈，不写成完全失忆 |
| D | 主“睡觉”＋辅“梦”＋辅“忘记”＋海盐 | sleep=1.64，dream=0.6，forget=0.6 | 睡眠改善，梦到熟悉背影，却认不清细节 | 同上；优先组合片段，不拼接完整回忆与记忆缺失 |
| E | 构造候选药效：睡眠持续至次日下午 | sleep 达标，时长违反明确要求 | 不发货，不展示发货后续 | 负例：证明标签命中仍可能不合规；不是现有原料已能算出的时长 |
| F | 主“累”＋海盐 | sleep=0.6，calm=0.6 | 不发货，不展示发货后续 | 现有标签条件即可拒绝，明确提示 sleep 未达 0.8 |

B / D 的 sleep 计算：`1.0 + 0.4 × 0.6 + 0.4 = 1.64`。所选原料没有强度修正，所以不发生额外强度缩放。这些数字是静态配置推算，不是已实现 Potion 模块的输出。

## 四、模板与片段样稿

共同开头：

> 店主，还是我，又请面包坊的伙计替我写几句。

共同基础反馈：

> 昨晚终于睡踏实了，隔壁酒馆什么时候散的，我都不知道。今天搬货，手上也有劲了。

在上述共同段落之后，各配方只添加对应的兼容内容：

### A：睡眠为主

> 今晚妹妹回来，我想早点吃完饭，早点歇着。多谢你。

### B：睡眠＋梦境

> 夜里还梦见了我娘，只有短短一会儿。醒来以后，我把这个梦讲给妹妹听，她让我也替她道声谢。

### C：睡眠＋遗忘

> 那些让我难受的事淡了一些。可今天妹妹提起娘以前唱的歌，我一时想不起调子。她又唱了两遍，我还是没接上。

### D：睡眠＋梦境＋遗忘

> 夜里像是见着一个熟悉的背影。我知道那个人对我很要紧，可转过脸是什么样，醒着想也想不清。妹妹问我梦见了谁，我没答上来。

D 使用组合片段覆盖 B / C 的相关单效果片段，避免同时声称“认出了母亲并详述梦境”与“无法识别梦中人”。睡眠基础反馈继续保留，额外效果不替代订单主效果。

样稿以朴素叙述保持代写信的口吻。上述新增家庭细节仅为待讨论文案，尚未写入人物事实库；后续模板不能在没有内容配置支持时自动推导出这些细节。

## 五、确认 / 重置推演

设进入炼制界面的本单基准为 S0：首信已读、相关词已剪、订单已接，材料尚未投入；前一单已确认。用 A 发货后，保存待确认结果 PA，正式世界仍为 S0。

| 操作 | 预期结果 |
|---|---|
| 阅读 PA 的直接后续 | 只能查看与选择确认 / 重置；不可剪词、领附件、接下一单、购物或跨天 |
| 重置 A | 丢弃 PA，回到 S0；海盐和消耗词条不丢失，无收入、状态或计数残留，首信剪词与前一单保留 |
| 改做 B | 从 S0 生成 PB，不叠加 A 的试验结果；看到 B 的直接后续 |
| 确认 B | 保存 S1，应用 B 的消耗、收入、状态和直接后续一次；正式进度只记录 B |
| 重复点击确认 B | 保持 S1，不再发收入或重复修改人物 |
| PB 阶段退出重进 | 恢复同一个 PB，仍可确认或重置，不重新抽取事件 |
| 确认保存失败 | 保持 PB 待确认，正式世界为 S0，不派发正式发货通知；再次确认成功只提交一次 |
| 重置后采用同一配方 B | 同一基准得到相同事件事实，避免通过重置刷随机结局 |

以上为状态设计推演，库存恢复、存档故障与重复确认需要实现后实测。

## 六、本轮检查结果与下一步讨论

| 检查项 | 纸面结论 | 仍需验证 |
|---|---|---|
| 四种配方在基础槽位内可表达 | 静态配置支持 | 实际 UI 投料与库存 |
| A～D 的睡眠标签达标，F 不达标 | 静态权重推算支持 | Potion 与 Order 的运行结果 |
| A～D 满足完整字面要求 | 尚不能确定 | 时长、速度、残留与工作能力换算 |

| 梦境＋遗忘表达无明显自相矛盾 | 组合样稿可避免冲突，组长已认可表达 | 记忆作用域与效果交互规则的配置实现 |
