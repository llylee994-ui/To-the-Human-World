## 共同行为约束

- 用户要求：“全界面位置挪到最左侧”“全界面”。普通场景、炼药、拼贴全部使用同一公共托盘，不能只改一个入口。
- 词条区取消滑动，保留直接拖拽；底部左右箭头分页。原竖向分类纸签、花束、布底和收起箭头沿用。
- 不重画词卡底纸、不将花草烘焙进词条。空白纸条是独立无字装饰。
- 药性窗口不展示“可能药效”及提前透露的剧情结果；仅展示当前药性、条件、是否满足和可选数值。
- 回溯日期不使用头像、风景缩略图，不增加逐日图片生成需求。
- 用户明确：电脑结局已居中，手机不居中。不能为修手机将电脑整体挪偏。
- 已确认的故事、11封信流程、结局路线条件、BGM和音效继续保留。除回溯所需事务外，不修改经济和剧情规则。
- 不操作桌面鼠标键盘、不用子代理。执行时遵守项目本地预览状态/刷新规则；只有用户要求更新手机预览时才走 Maker 提交构建与二维码流程。
- 参考图只确定布局；图中日期、词条、库存、数字是示意，运行时使用真实数据。

## 1．公共托盘：贴左、分页、减小标题

**涉及文件：** `scripts/ui/landscape/WordTrayDrawer.lua`、`WordTrayArt.lua`、`WishTray.lua`、`BrewView.lua`；新增纯布局模块 `scripts/ui/landscape/WordTrayPages.lua`。

**方案：**

- 抽屉整体使用全屏坐标的 x=0；安全区只用于具体操作目标，不再把整块布和托盘向右推。覆盖普通词条入口、炼药入口、拼贴入口以及关闭后重开的状态。
- 标题和底纸一起缩小到约原来的六成，做成低存在感的小纸签。
- 删除词卡区的 ScrollView 触摸滚动，改为固定区域内分页。每页容纳数量由真实纸条尺寸、行间距和当前可用高度计算，不能统一拉长词条或机械规定每页几张。
- 底部“左箭头／页码／右箭头”固定位置；首尾页禁用相应箭头。每个分类保留自己的页码；旋转屏幕或尺寸变化后页码收敛到合法范围。
- 分类继续使用原竖向纸签，根据可用高度排布；无法全部容纳时提供可点击的分类组切换，不把分类藏进只能滑动触达的容器。
- 原收起箭头保留，和分页区域错开，不能压住最后一张词卡。

**接口：** `WordTrayPages.Build(cards, width, height, measure)` 返回 `{pages, pageCount}`；每页元素 `{card,x,y,w,h}`。`measure(card)` 使用现有 `WordSlip.Metrics`。页码、分类、打开进度只属于视图状态，不写玩法存档。

**实施与验收：**

- [x] 用真实词卡尺寸覆盖短词、长词、最后一页、空分类、窄屏与尺寸切换，验证每张词卡完整落在页内、互不重叠。
- [x] 替换公共托盘的卡片区并接入分页；WishTray 只提供词条/装饰取用行为，不能另造托盘外壳。
- [x] 普通、炼药、拼贴逐入口检查 x=0、收起/重开、分类页码；浏览和翻页不增加存档写入。
- [x] 验证手指拖词时不再引发托盘滚动，翻页箭头不触发词卡拖拽，原音效仍按一次有效动作播放。

纯布局测试要验证的关系示例：

```lua
local result=Pages.Build(cards,160,180,measure)
assert(result.pageCount==#result.pages and result.pageCount>=1)
for _,page in ipairs(result.pages) do
    for _,row in ipairs(page) do
        assert(row.x>=0 and row.y>=0)
        assert(row.x+row.w<=160 and row.y+row.h<=180)
    end
end
```

## 6．标题新增进度回溯：真实逐日快照

**涉及文件：** `scripts/ui/landscape/TitleView.lua`、`AppView.lua`、`scripts/ui/PlayModel.lua`；`scripts/core/GameState.lua`、`GameSession.lua`、`SaveSchema.lua`、`scripts/systems/ReleaseCoordinator.lua`、`ReleaseChapterAudit.lua`；新增 `scripts/systems/RewindHistory.lua` 和 `scripts/ui/landscape/RewindView.lua`。

**现状与边界：** 当前 SaveSystem 为A/B双快照＋提交记录，覆盖轮换；现有 chapter.checkpoint 是结局前快照，不是完整逐日历史。不能据此声称旧版本已经保留任意一天的开头。

**界面：**

- 标题菜单增加“进度回溯”。只展示当前这轮，不混入旅途留念或上一轮记录。
- 日期用文字和简单节点，显示当前日、选中日、可回溯状态；没有头像，也不生成逐日缩略图。
- 选中日后显示可恢复时间点与摘要，明确按钮“回到第N天”。日期多时使用分页，不能把所有节点缩成难点的小字。

**状态与存档方案：**

- 新增独立业务模块 RewindHistory 管理“本轮编号、版本、日开头快照、回溯前备份”。快照保存完整业务投影，但排除回溯历史自身，防止递归复制；音乐/音效设备设置不回滚，跨周目留念保留当前全局值。
- 在 StartJourney 和每次成功 NextDay 时建立日开头快照，与该次主状态一起提交；跨天失败不能留下一个假的已到达日期。结束第11天若进入结局，不伪造第12天。
- 通过 GameState 增加查询与回溯命令，候选先完整验证，再用既有原子提交路径替换状态。恢复金币、库存、词条来源、来信/订单、采购、设备、当天捞瓶次数、剧情事实和本轮结局阶段，不能只改 day。

- 回溯创建新的 revision，不能恢复旧 revision 导致旧界面回调重新变得有效。失败保留现状；提交结果未知仍走原有锁定/重新读取对账逻辑。
