# 主线路线编辑器 Implementation Plan

**Goal:** 展示实际剧情路线，填入可讨论的完整梗概，并支持逐节点编辑与试走。

**Architecture:** 沿用 Python 本机保存服务和共享 JSON。新增纯函数路线布局模块，画布按轮次及实际边排布；模板与节点实例分开，主线流程通过带条件的箭头连接。

**Tech Stack:** Python 标准库、原生 JavaScript、SVG、现有 Playwright/Chrome。

## Global Constraints

- 用户已授权实施，不另加设计审批；本轮不提交、推送或运行 Maker 构建。
- 案件事实与身份规则按既有文档；新增18轮排期属于讨论稿。
- 只编辑独立编辑器和主线讨论数据，不改游戏运行代码。
- 旧图备份；写入使用乐观版本保护；不输出本机 API 令牌。

## Tasks

- [x] 1. 写路线纯函数与保存校验测试：布局只读 edges，按 round/step 下行，相关路径、结果压缩、模板字段和倒流校验。运行确认缺实现失败。
- [x] 2. 实现 routes.js、map.js 路线模式，保留旧图显示；app.js 加轮次导航、模板字段、场景/结果视图和试走按钮。服务提供新模块。
- [x] 3. 保存旧图快照，创建梗概生成脚本并通过本机 API 写入18轮流程：具体分岔、不同后续、远处汇合、案件与身份双轴。新增结果均有出口，不产生免费证据。
- [x] 4. 浏览器验收展示、字段保存、模板绑定、真实支路导航、试走、撤销、冲突保护和窄窗口；审读截图。修复失败，再运行相关检查。
- [x] 5. 更新使用说明、梗概阅读说明、工作记录，刷新已有编辑器并展示。

执行在当前共享工作区按任务进行，避免切换工作区导致正在使用的编辑器读到另一份数据。
