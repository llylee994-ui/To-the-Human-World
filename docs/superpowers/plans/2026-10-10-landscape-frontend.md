# 《寄往人间》横版前端实施计划

> **For agentic workers:** 使用 `executing-plans` 按任务执行并核对验收项；未经用户授权不自行派生其他会话。步骤用复选框记录。Maker 项目提交使用官方 `maker_build_current_directory`，不使用独立 Git 提交、推送或 PR 流程。

**Goal:** 将现有文字按钮试玩界面替换为横版海边药铺，完成收信、剪词、投料、试做、重置、发货与记录回看的手机操作闭环。

**Architecture:** 分层 2D 药铺包含桌前、海边、炼药三个视图，用平移或短淡入过渡连接；词条栏与记录书为侧面板，商店、案件板和阅读为独立浮层。全部界面使用同一个 GameSession；业务操作通过 PlayModel，列表通过只读查询接口，动画不修改库存和存档。

**Tech Stack:** UrhoX Lua 5.4、`urhox-libs/UI`、分层 PNG、现有排版编辑器导出信息；使用 UI.Scale.DEFAULT、SafeAreaView、DragDropContext / ItemSlot 与 UI 动画。

## 1. 需求与方案默认值

### 用户明确要求

1. 左侧窗户、窗外海景与商船；右侧木架上摆草药等非词条原料，药罐在右侧。
2. 窗前桌子与抽屉；桌上有网兜、日历、钱袋、桌布、剪刀、托盘、档案袋、记录书和装饰。
3. 网兜进入海边；海边有开始捕捞与返回药铺，主界面和海边都能点击商船进入商店。
4. 顶部固定显示金币；日历数字动态显示；钱袋和单独的剪刀只是装饰。
5. 抽屉存所有已收来信，包括剪完和未剪完的信；可再次展开未剪完的信。
6. 托盘打开左侧分类词条栏；档案袋进入主线案件板；各面板有触屏可用的关闭按钮。
7. 配方书入口改为记录书。按故事分页、侧边书签；保存配方、后续和星级，即使重置仍保留；点击具体记录查看详情。
8. 进入炼药视图默认打开左右侧面板；中心药罐、后方原料架；词条和原料拖入锅中；底部返回桌前、开始熬制。
9. 返回桌前自动收起左右面板；来信及后续阅读为全屏遮罩、背景虚化、可关闭。
10. 第一张选中词卡默认主词，后续辅词；槽内词卡可点击取出。已剪信纸不显示“缺口”字样。

### 本计划采用的实施默认值

| 尚未由用户逐项定案的选择 | 本计划默认处理 | 调整时涉及 |
| --- | --- | --- |
| 后续显示时机 | 先试做并看后续与星级，再选择重新熬制或发货 | 程序侧订单事务 |
| 取出主词后是否自动晋升辅词 | 主词留空，下一张投入的词补主词；已有辅词不自动改身份 | 交互模型 |
| 捕捞升级 | 第一版每日成功捕捞一次；升级次数和价格不在本轮制定 | 程序侧捕捞计数、后续内容供给 |
| 无订单熬制 | 可进入场景和查看库存，开始熬制提示先从来信接单；不伪造自由实验订单 | 新自由实验模式需另定消耗与记录 |
| 未熬制草稿 | 返回桌前和退出恢复保留已保存投料 | 程序侧 schema 3 草稿 |
| 熬制前补剪词、采购 | 允许；待处理结果未决定时锁定变更，仍可只读查看 | 程序侧冻结基准时机 |
| 结束当天 | 点击日历打开小确认层，执行已有跨天业务 | 跨天门禁与草稿清理提示 |
| 同一后续多次试做 | 书页合并同一后续，保留各次配方和状态；不提前展示未发现分支 | 程序侧记录查询 |

默认值需要改时，先同步修改两份计划的对应条目；不要在两个实现中各自选择相反行为。

## 2. 布局、场景与素材清单

### 2.1 桌前 HomeView

- 左侧窗户占主要景观区；海面上的商船作为单独可点对象，不烘焙在底图。
- 桌面居中，网兜靠窗，托盘、抽屉把手、档案袋和记录书各有独立热区；装饰不能遮住入口。
- 右侧原料架与药罐组成进入炼药区的视觉引导。窗户、木架不是额外菜单。
- 日历底座使用图片，日期用 UI.Label 叠加；钱袋不显示第二份余额，不出现点击购买金币。
- 对网兜、抽屉、托盘、档案袋、书、药罐、商船提供按下反馈；首轮可在点按时显示短物件名。不可点击装饰不使用同样的高亮反馈。
- 收到新瓶后的演出结束打开来信阅读；读取与收信成功以后才刷新抽屉内容。

### 2.2 海边 SeasideView

- 保持主界面窗外的海岸、码头和商船视觉关系；可用放大背景与分层元素实现，不依赖 3D 摄像机。
- 捕捞按钮显示“开始捕捞（剩余 1 次）”；无次数、无可收信件、待处理订单锁定分别给出玩家可理解原因。
- 捕捞演出不提前扣次数。请求成功保存后再显示收获；空海不伪造瓶子。
- 商店关闭回海边；返回药铺回桌前。中断捕捞动画不得再次发送同一收信命令。

### 2.3 炼药 BrewView

| 区域 | 默认布局 | 手机限制 |
| --- | --- | --- |
| 左侧约 24% | 分类词条栏、卡片与可用数量，标题处关闭按钮 | 分类页签横向滚动；卡片纵向滚动，拖拽与滚动区分 |
| 中间约 50% | 后方原料架、药罐、订单必要条件、已投主辅词和原料摘要 | 药罐投放区始终可见；架上原料位于左右面板之间 |
| 右侧约 26% | 半页记录书、故事书签、记录摘要，书签栏顶部关闭按钮 | 摘要可滚动；完整正文点击后全屏阅读 |
| 中央底部 | 返回桌前、开始熬制或继续处理结果 | 按钮固定，不跟随书页滚走 |

比例是构图起点，不是锁死像素。默认两侧展开；常用横屏手机适配时优先减少卡片列数和书页摘要数量，不能把文字和关闭按钮一起缩成不可操作的小图。极窄窗口作为降级适配，不计为手机主验收设备；若确实需要自动折叠，先在两份方案中记录该变更。

每张已投词卡显示主词/辅词身份，原料显示份数，空主词位显示“主词未选择”。卡片可以点击取出，不要求再从锅里精确拖出。

### 2.4 分层资产与布局数据

前端先核对 `docs/设计/B窗口_分层素材规划_v01.md`、`docs/actions/2026-10-09-b-seven-source-cutouts.md`、`docs/actions/2026-10-09-b-right-shelf-background.md` 及 assets 真实清单。已有抠图优先复用；缺失资源写明物件、用途、遮挡恢复和透明需求，不自动生成整套新素材。

建议分组：干净室内底图、窗外海景、商船、前景桌子、抽屉与把手、托盘、网兜、日历底座、档案袋、记录书、原料架、药罐、草药瓶、装饰，以及卡片与阅读纸张背景。

排版编辑器仍是素材定位工具，不等于运行界面。检查导出结构再编写 `LayoutManifest.lua`，将素材路径、锚点、相对大小、层级、热区关联到稳定物件 ID。不得把开发机绝对路径或 `.local` 缓存直接作为游戏资源引用。

### 3.1 已有接口与新增接口

已有：`model.Read(instanceId)`、`Cut(spanId)`、`Accept()`、`Buy(ingredientId)`、`Preview()`、`Resolve(true/false)`、`NextDay()`、`Reload()`。它们均受业务门禁约束，不能靠页面显示判断已成功。

新增契约由程序计划第 3 节交付：

```lua
-- 下面为拟新增接口示意，当前不能直接运行。
local letters = session.queries.GetLetters()        -- Result<LetterRow[]>
local tray = session.queries.GetWordTray()           -- Result<WordTrayView>
local stories = session.queries.GetJournalStories() -- Result<JournalStory[]>

local record = session.queries.GetAttempt(transactionId)
local salvage = session.queries.GetSalvageView()
local order = session.queries.GetOrderSummary()
local shop = session.queries.GetShopView()
local board = session.queries.GetCaseBoard()

model.Drop("word", tokenId)      -- 自动安排主/辅位置，Result<Draft>
model.Drop("ingredient", ingredientId)
model.TakeOut("word", tokenId)   -- 不根据字面猜来源
model.TakeOut("ingredient", ingredientId)
model.ReturnHome()               -- 仅导航，不确认、不重置、不清草稿
model.OpenAttempt(transactionId) -- 历史只读，不再次熬制
```

前端先用当前查询封装或独立 fixture 做布局；新增接口未实现时禁止混入真实存档。接口联调时以 Result.ok 和刷新后的视图为准，任何返回副本都不写回模块。

## 4. 导航、拖放与阅读细则

### 4.1 统一关闭规则

| 场景 / 面板 | 关闭后行为 | 不能发生 |
| --- | --- | --- |
| 商店 | 回进入前 home 或 seaside；刷新真实余额 | 重新进入主页、自动购买 |
| 抽屉 | 回原场景，保留选中信件 | 清空信件或恢复已剪词 |
| 词条栏、记录书 | 各自关闭；炼药区提供重新打开入口 | 删除投料或记录 |
| 来信 / 历史后续阅读 | 回原场景 / 书页及原滚动位置 | 接单、发货、重新结算 |
| 当前待处理后续阅读 | 收起阅读，锅上保留待处理标记 | 默认为发货或重置 |
| 案件板 | 回进入前场景 | 修改人物状态 |
| 返回桌前 | 取消拖拽、切 home、收起左右面板 | 调用 CancelBrew / Reset / Confirm |

关闭按钮视觉可以是小 ×，触摸热区建议不少于 44×44 UI 基准像素，并放在 SafeAreaView 内，不能与平台胶囊重叠。模态层阻止点击穿透，侧面板只占自身区域；透明全屏容器不能吞掉锅口拖放。桌面可支持 ESC，但手机操作不依赖键盘。

### 4.2 投料

1. 拖拽数据使用 `{kind="word", id=tokenId}` 或 `{kind="ingredient", id=ingredientId}`；词卡不能只传 wordId。
2. 拖动过程中只画跟随影像，不更改库存、草稿或存档。
3. 手指松开且命中明确锅口 / 锅周投放区，调用 model.Drop；其它区域取消，原物件保持。
4. 成功保存草稿后才更新已投摘要、暂用数量和入锅动效；失败时弹回，显示槽位满、库存不足或待处理锁定等原因。
5. 同一卡不能同时占主辅槽。已选词在托盘保留位置但标记“已投入”，可用筛选不得丢掉来源。
6. 长列表以滚动为默认意图，设置拖拽触发阈值；点击词卡提供等价投料，点击已投卡取出。阈值以手机实测调整，不写死成未经验证的引擎参数。
7. 导航、弹出阅读、切后台或开始熬制都取消未完成拖拽，避免释放到错误页面。

### 4.3 订单提示与结果

- 按 GetOrderSummary 显示订单必要条件和 reason；当前 v02 主轴看成品主辅合计，不写成必须选择某种主词的硬限制。
- 不泄露未发现的后续、全分支列表或原始数值调试信息。失败说明使用玩家语言，原始路径留日志。
- 开始熬制后禁用重复提交；业务结果成功保存以后播放烟雾。演出可跳过，但跳过只改变显示。
- pending 后全屏显示已保存正文与星级，底部固定重新熬制 / 发货；历史阅读没有这两个业务按钮。
- 发货失败保留待处理页；保存不确定时锁定写操作并引导同槽恢复，不显示奖励已到账。
- 字面条件不足时显示药效反馈并留在配料阶段，不生成有星级的假成功故事。

### 4.4 抽屉、词条栏、记录书与案件板

- 抽屉列出已收到的信件，展示未读、未剪数、订单状态；阅读纸张按真实 segments / spanId 构建。已剪位置用留白或剪口，不出现字面“缺口”。
- 词条分类使用已配置类别，并保留来源区分。主线和普通来源不能被同名分组合并成一张可无限使用的词。
- 记录书侧边只列已收到故事标题，按故事一个逻辑页；书页很长时滚动，保持书签与关闭按钮固定。
- 同一后续分组下展示不同配方与试做状态；未发现分支不显示其标题，也不预先标出五星等不存在的评分。
- 每次试做记录状态为待处理 / 已重置 / 已发货；星级读取保存结果。历史详情不重新调用生成器。
- 案件板只展示程序侧返回的已解锁节点与联系；当前运行内容无真实主线线索时显示未开放状态，不用样例冒充正式案件。
