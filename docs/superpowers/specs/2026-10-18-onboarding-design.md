# 《寄往人间》新手引导设计 v02

日期：2026-10-18。v02 以本轮用户手机截图反馈为准：炼药五项均只介绍、点“知道了”继续；“开始熬制”是最后提示，之后不再引导结果或寄出。概念图保留作视觉参考，不代表当前交互规则。

## 1. 已确认方向

- 新游戏进入室内后，压暗画面，桌面无署名便签亮起，点击后展开开场白。
- 收起便签后高亮门边网兜，再依次引导进入海边、开始捕捞、打开来信、剪词和接下委托。
- 首次进入炼药工作台时，逐项介绍左边词条栏、右边记录书、中间原料、“条件与药效”和“开始熬制”。
- 炼药区所有讲解均点击“知道了”推进，不要求投词、投料、打开条件或熬制；不锁工作台输入、不把离开的玩家拉回。
- “开始熬制”讲解确认后立即完成引导；结果页、寄出与重新调配不再出现新手引导。
- 引导可跳过、可中断续接；新旅程重新触发。已有旧存档不补弹开场。

## 2. 叙事与开场便签

位置仍为现有“人间之外”的海边魔药铺，不新增未确认的地名。玩家因为未完成的愿望来到这里，身份及愿望内容不在开场揭晓。人间不知道药铺存在，瓶中文字来自人物念头，不写成人物主动向药铺求药。

便签无姓名、落款、头像或旁白人物。界面教学提示与便签正文分开呈现；普通人物信件不承载新手说明。

### 便签正文草案

> 这里是一间在人间之外的魔药铺。
>
> 你因一个尚未完成的愿望来到这里。
>
> 海上漂来的瓶子，装着人间某个人的心事。把它们捞起来，读过信，剪下能用的词语，配上原料熬成魔药，再照着地址寄回人间。
>
> 网兜挂在门边。先去看看吧。

便签展开后不显示标题，只显示正文；“桌上有一张没有署名的便签。”作为点击前的场景旁白显示，展开后收起。收起动作标为“收好便签”。正文一次完整展示，长屏可正常滚动，不使用强制打字等待。之后可从帮助入口重读；不替换现有信纸、信件抽屉或读信入口的正常用途。

## 3. 分步流程

| 步骤 | 画面与提示 | 完成依据 |
|---|---|---|
| intro.paper | 新旅程首次室内画面稳定后渐暗，桌面纸张保留暖光；画面下方旁白“桌上有一张没有署名的便签。” | 正确纸张被点击 |
| intro.note | 中央展开旧纸便签，室内留在背后；显示正文与“收好便签” | 玩家主动收起 |
| home.net | 遮罩保留，光区移到门边网兜；“先去海边看看。” | 正常网兜入口成功进入海边 |
| sea.salvage | 海面与漂流瓶可辨认，高亮“开始捕捞”；“捞起这个漂流瓶。” | 捕捞成功且收瓶动画完成 |
| sea.read | 高亮实际阅读入口或收起的瓶子；“看看瓶子里写了什么。” | 来信展开且布局稳定 |
| letter.cut | 聚焦一处仍可剪的正文词语；“点亮起的词语，把它剪下来。” | 真实剪词命令成功且纸条收取动画结束 |
| letter.accept | 指明愿望及委托笺，再提示“准备好了，就接下这份委托。” | 接单成功并进入炼药工作台 |
| brew.word | 高亮左侧词条栏，介绍词条用途 | 点“知道了” |
| brew.book | 高亮右侧记录书，介绍来信与后续故事 | 点“知道了” |
| brew.ingredient | 高亮中间原料，介绍原料对药性的影响 | 点“知道了” |
| brew.conditions | 高亮“查看药性与条件”入口，解释用途 | 点“知道了”，无需打开 |
| brew.ready | 高亮“开始熬制”，解释满足条件后可查看结果 | 点“知道了”立即结束引导，无需配方或实际熬制 |

`result.explain` 和未完成的旧 `complete` 状态只作为旧存档兼容入口，载入即安静完成，不再弹框、打开结果页或要求发货。

剪一张词后不强迫立刻接单，保留继续阅读与剪词的机会。需要明确提示可继续剪取亮起的词；玩家自行决定何时接下委托。

## 4. 视觉与动效

- 延续现有旧木、奶油纸面、植物刺绣、海蓝和暖金色，不引入现代蓝色教学卡片或大号卡通手指。
- 默认遮罩约 55%–65% 黑褐色透明度；具体以室内与海面可辨认为准。目标保持原有美术，辅以细暖光边，避免白色实心描边或大面积过曝。
- 单次只引导一个动作。拖动教学可同时露出来源、落点与它们之间的操作路径。
- 提示为小纸笺，一至两句，靠近目标但不盖住目标；说明步骤带“知道了”，操作步骤由真实操作成功推进。
- 纸张从桌面向中央展开，收好后暖光移到网兜。转场期间先淡出当前光区，到达目标画面再点亮下一处。
- 目标轻缓呼吸；布局稳定后开始，尊重减少动态效果设置，关闭呼吸不影响提示含义。
- 右上角保留清楚、低调的“跳过引导”。跳过不授予词条、原料或奖励，不自动捕捞、接单、熬药或发货。
- 新手期间隐藏与当前任务无关的物件提示标签，避免整屋同时亮起；退出引导恢复原来的提示开关状态。

## 5. 新旅程、恢复与容错

- 首次“开始游戏”及确认“新的旅程”均建立本旅程引导状态；“继续游戏”仅恢复未完成的步骤，不从开场重播。
- 进度跟随当前旅程存档，包含版本、当前步骤、是否完成/跳过、便签是否读过。旧存档缺少这些字段时默认不强制启用；新旅程初始化时明确启用。
- 重入时核对真实进度：已收瓶不再捕捞，已剪词不重复剪，已接单直接恢复工作台；炼药说明在工作台恢复显示；已进入旧结果引导状态则安静完成。
- 捕捞、阅读、剪词、接单按真实成功和动画完成推进；炼药五步只按玩家点击“知道了”推进，不监听配方、试做或发货事件。
- 设置、应用切后台、竖屏提示、资源加载页优先于引导。恢复后重新取得目标布局，高亮不跟随旧坐标。
- 目标不可见时允许当前步骤所需的滚动，目标尚未生成时暂停高亮；不会只留下一个无法点击的黑屏。
- 引导层不重复发送业务命令，不重放已完成的事务。关闭/销毁时清理监听、拖动状态与光区。
- 从结局恢复或回溯到教程完成后的经营进度不重播。新旅程仍保留原有结局留念政策。

## 6. 现有接入位置与边界

仅为后续实现导航，当前没有修改这些文件：

- `scripts/ui/landscape/TitleView.lua`、`AppView.lua`：新旅程/继续入口、室内及场景切换。
- `HomeView.lua`、`LayoutManifest.lua`：纸张、网兜的实际物件位置；复用现有美术和投影。
- `SeasideView.lua`、`SalvageController.lua`：开始捕捞、捞瓶演出、阅读入口。
- `LetterPresentation.lua`、`LetterPaper.lua`、`ReaderOrder.lua`：展开、可剪词的实时边界、剪词成功和接单。
- `BrewView.lua`、`WordTrayDrawer.lua`、`JournalBook.lua`、`BrewRecipe.lua`、`PotionNotesView.lua`：工作台五个教学目标。
- `ResultView.lua`、`ui/PlayModel.lua`：结果提示与业务成功反馈。
- `AssetPreloader.lua`、`LoadingView.lua`：等待资源门禁完成，再显示引导。

后续实现建议使用独立引导状态控制器、步骤数据和展示层；业务逻辑仍使用现有协调器。显示/关闭说明不改变委托、库存、配方或结局。UI 使用现有 urhox-libs/UI，目标按实时布局和现有画面投影定位，不把概念图坐标写死为手机坐标。

当前真实按钮名称为“条件与药效 ›”，图上、步骤和实际入口保持一致；不在本轮顺带改名。药性手札沿用当前正式内容版本的炼制条件判断，不把所有说明项都宣称为强制门槛。

参考现有主页和工作台实机存档，只新增引导的表现层。工作台图示优先演示左词条栏到锅口的一个动作；右记录书、中间原料、条件入口和熬制按钮将在后续步骤分别亮起。

完整生图提示词保存为 `../../设计/原型/onboarding-v01-prompt.txt`，使用内置 image_gen，原始生成文件保留，项目保存原字节副本。实际输出为 1672×941 RGB，四格设计板，不是单屏运行资产；提示词中的分辨率期望不代表实际输出。概念美术不接入运行资源清单，也不触发构建或重启。

## 8. 后续验收标准

1. 新旅程从加载结束到便签聚光、展开、收起、网兜转场的连续流程可完成，没有底层误触。
2. 捕捞、阅读、剪词和接单均为真实命令，成功一次推进一次，动画期间重复点击不重复获取词条或委托。
3. 首锅允许不同合法选词、不同原料与不同结果，不把某个配方或三星结果设为引导通关条件。
4. 条件未满足时能调整配方、补剪词或访问必要采购入口，不被强引导堵死；返回工作台后从未完成步骤继续。
5. 试做返回可再次熬药；真实寄出成功才完成引导，奖励与库存结算只发生一次。
6. 每个步骤退出重进、切后台和旋转后都能恢复；首次加载、字体布局和场景动效不与光区抢层级。
7. 跳过可在每步使用；旧存档不强制重播；新旅程重新启用；结局留念不受影响。
8. 桌面横屏与手机横屏分别检查遮罩、目标命中、拖动路径、安全区、长文滚动与按钮可达性。概念图和无头测试不代替真机验收。

## 新旅程入场补充（用户已确认）

标题界面淡黑 → 室内渐显，但保持昏暗 → 桌上便签亮起 → 出现旁白。

时序为 0.4 秒标题淡黑、0.7 秒室内渐显、0.3 秒便签光区渐亮、0.35 秒底部旁白淡入。黑场全不透明时才切场；室内布局未就绪时保持黑场。输入在演出结束时释放；失焦、最小化、竖屏或设置打开时暂停。标题的新旅程开场播放，读过/进入后续步骤的继续游戏不重播。旁白为“桌上有一张没有署名的便签。”；点击后收起旁白，展开的便签无标题。全部为表现时间，不自动阅读便签、捕捞或修改库存。
