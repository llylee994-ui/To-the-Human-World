## 必须落实的用户反馈

- 所有场景的公共词条托盘都贴物理屏幕最左边，复用现有 WordTrayDrawer，美术结构不另造。背景可延伸至安全区，操作目标单独避开硬件遮挡；不能为整个托盘留左侧空白。炼药、普通浏览、拼贴等入口全查。
- 缩小“词条栏”标题和底图；改成同款小纸签。词条区域取消滑动，底部左右箭头分页；原有收起箭头保留并与分页避开。分类仍用原竖向纸签，超出空间时也要可点击到，不能藏在只可滑动的区域。
- 字条按实际字体测量宽度加固定内边距，不能强迫占半栏或整栏；单字、双字、三字、长词都校验。原纸纹和折痕保留，缩放不要把文字与底纸拆开。主/辅仅在药槽/配方位置显示，托盘不加撑高卡片的角色标记。
- “条件与药效”点击后，从炼药区下方展开大号药性手札窗口；覆盖原料栏与药槽，不挤压其布局。关闭恢复原画面。阅读字号和行距以手机为准。
- 后续故事尽量使用屏幕可用高度和宽度，减小头部重复信息；平台胶囊只避让可能碰到的按钮，不因此把整张纸推下去。
- 旅人、学徒、愿望终幕一起验证：标题、副标题、返回按钮使用共同中心轴，按完整手机画面检查；不能只在电脑16:9截图验收。
- 商店购买前后固定主体和商品卡几何；反馈作为覆盖提示，不新占一行高度。
- 标题新增“进度回溯”，只显示当前这一轮已到达日期，恢复当天开始时的完整业务状态。图中7天仅为例子。该功能需要完整快照/事务支持，不能直接改 day 字段；旧存档可恢复范围和回溯前备份需在实施前据实际存档能力明确。
- 拼贴信纸铺满托盘以外的主工作区，保留小角花，顶部集中撤销/暂回首页/预览寄出，标题小且不挤占纸面。空白纸条仍是独立无字装饰，花草不烘焙到词条底纸。
- 词条和装饰从托盘直接拖入纸面，取消点击即添加。纸面允许覆盖；实际收集词条每张一次，装饰可重复。点选或开始拖动时显示贴着选中素材的浮动小工具框，点空白处隐藏；框内只有上一层/下一层、锁定/解锁、收回，不保留固定底部操作栏。
- 删除左转、右转、缩小、放大四个按钮；扩大旋转与缩放手柄的可触区域与杠杆距离，重新校准旋转/缩放灵敏度。工具框和手柄跟随素材及其变换，接近纸边时自动避让。手机单指拖动、旋转、缩放和双指手势的指针所属要逐项验证。

## 已读取代码中的直接线索（还不是手机修复验收）

- WordTrayDrawer.Render 为角色标记传 reserveTop=18，WordSlip.Metrics 把它计入高度；同时强制 minWidth=half 或 available，导致纸条被撑到栅格宽。应把显示角色与纸条几何解耦，按真实字宽布局。
- ShopView 的 shopMessageArea 是普通布局子节点，height=44、flexShrink=0；AppView.UpdateChrome 在有购买消息时 SetVisible(true)，占用内容区高度，符合“购买后缩矮”的现象。新提示应覆盖展示，购买流程和库存事务不改。
- 普通托盘 panelLeft 使用 safeInsets.left，炼药 workbench 则使用0，这解释了同一托盘在不同场景有不同左边距。
- DepartureView 为三个结局共用演出底层，目前根据不对称安全区计算中心；后续需使用完整屏幕坐标复核，并为按钮单独做安全避让。
- ResultView 有宽度上限和胶囊避让引起的整体下推分支；后续用用户2412×1080横屏比例检查纸面与关闭目标，避免对全文阅读面板保留不必要的顶部空带。
