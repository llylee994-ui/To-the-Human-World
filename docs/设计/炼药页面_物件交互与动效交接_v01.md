## 2 页面空间与物件布局

### 整体画面

正式游戏是 Maker／Lua 的横屏 2D 前端，设计坐标为 1920×1080。炼药页表现玩家坐近主页右侧工作桌，视点略俯，能看清锅口和后方取料位置。沿用同一只药炉、同一室内空间的暖木材质、草药生活痕迹与冷暖关系，保持现有透视、光向、笔触和细节密度。

| 空间 | 物件与用途 | 构图约束 |
|---|---|---|
| 左侧 | 连续的浅木词盘，承载程序排列的来源词纸 | 不画四个固定插袋或固定分类格；卡片数量、分类和滚动由实际库存驱动，给拖出动作留通路 |
| 中央后沿 | 一层矮原料架，摆四种原料容器 | 容器位于两侧面板之间；每种轮廓、内容物不同，锅体不能挡住取料区 |
| 药炉后上方 | 一张展开或靠在架旁的委托纸 | 留出短标题、要求和条件提示，点击查看对应来信；底图无格线与正文 |
| 中央前部 | 现有药炉及清晰锅口 | 锅口是投放目标；显示范围和点击范围分别由 C 处理 |
| 锅旁桌面 | 配料小纸签，记录主辅词及原料份数；搁置的搅拌匙可承载熬制入口 | 摘要可取回，熬制入口可辨识；具体造型随图稿审定 |
| 右侧 | 记录书与故事书签，纸面留白 | 桌面书只承载短摘要，点击打开既有记录界面；书的轮廓完整且与画面右缘有间距 |
| 画面边缘 | 不在底图烘焙返回或关闭图标，共用 HUD 和导航由程序另行处理 | v03 已移除左词盘 X 和左下箭头，书上也无 X；用户本次改图不等于已修改运行导航 |

此前方向是进入炼药视图默认展开左右侧栏、可分别收起；本轮调整为桌面可见词盘和记录书，右侧完整记录在点击书后展开，未打开时不占用长文阅读面板。24%／50%／26% 是早期横屏计划中的构图起点，不是固定比例。宽屏适配优先保证锅口、四个取料来源、文字和关闭入口可用，不靠整体缩小文字解决拥挤。

左词盘与右记录书都属于当前桌面上的可操作表现。背景需补全它们收起后的区域；画面中不烘焙不可移除的第二份书页或卡片。

### v01 纸张语义与本次修订方向

| 图中纸面 | 原本代表什么 | 后续方向 |
|---|---|---|
| 左边四叠纸卡 | 持有的词条实例 | 四插袋造成容量或类别固定的误读，应取消；采用连续词盘和可重复的独立空白纸卡模板 |
| 四个原料容器上的小纸签 | 原料名称、库存等短提示 | 保留小标签用途；内容由程序按真实状态绘制 |
| 药炉后上方大纸 | 当前委托的标题、要求与条件摘要 | 保留纸纹与边角装饰，正文区域空白；本轮采用点击查看对应来信的方向 |
| 锅前桌面带格子的纸 | 本锅已选主词、辅词与原料摘要 | 不是第二封信或固定配方；v02 已收简为小摘要纸，取消烘焙格线；后续须保留就地取回材料的能力 |
| 右侧摊开的书 | 已收到故事及试做配方、后续与评价记录 | 空白书页加少量装饰；本轮采用点击展开已有记录界面的方向，不新增独立配方解锁系统 |

截至本次核对，词条定义共 **8 类**：睡眠类、情绪类、记忆类、身体类、物件类、关系类、行为类、时间类。`GetWordTray()` 从实际库存中的词条实例产生 `cards` 和 `categories`，所以当前显示的类别不一定包含全部 8 类。图中四格没有契约依据，也不能改成固定八格；词库数量与当前锅的投料容量是不同概念。

所有可排字纸面只保留纸纹、外缘及避开正文的少量装饰。不把文字、固定表格框、卡片数量、星级和状态格烘焙进底图；程序按内容排版，单张空白卡模板可以重复使用。

点击进入详情是本轮采用的调整：工作台保留简短委托、本锅摘要和取料操作；长信件或完整记录在已有阅读／记录界面展开，关闭后回到炼药，保留草稿及待处理结果。具体返回链路须由 C 核对并实现，本轮没有验证现有界面已支持该流程。此调整不把每次选词、投料也改成跳页。

### 与现有入口的衔接

主页药炉入口的最新方向是整幅真实主页美术共同平移并等比放大，HUD 固定，结束后进入既有炼药功能页。旧几何转头已取消。本文件只设计炼药页及页内动作，不接管正在进行的主页入口实现，也不以旧的“仅药炉移动”方案替换最新决定。

## 3 物件与现行接口对应

以下查询简称均位于 `session.queries`，返回 `Result`，成功后读取 `.value`。表中展示字段省略了这层包装。`model` 指现有 `PlayModel`；`model.Refresh()`、`model.GetDraft()` 返回快照或草稿副本，不是 `Result`。

### 页面功能对象

| 前端物件或区域 | 数据来源 | 操作及业务含义 |
|---|---|---|
| 订单纸 | `GetOrderSummary()` 的 `title`、`requirementDesc`、`requirementHint` | 展示摘要；缺主词时 `evaluated=false`，不能画成已满足要求。点击读信方向见下文，尚未接入 |
| 词条托盘与分类纸卡 | `GetWordTray()` 的 `cards`、`categories` | `model.Drop("word", tokenId)` 投入；`model.TakeOut("word", tokenId)` 取回 |
| 原料架上的四个容器 | `content.ingredients` 定义；`model.Refresh().live.economy.ingredients` 库存 | `model.Drop("ingredient", ingredientId)` 加一份；`model.TakeOut("ingredient", ingredientId)` 减一份 |
| 药炉与锅口 | `model.GetDraft().equipmentId`；`content.equipment` 的容量 | 锅口承接同一套 `Drop`，炉体没有另一条投料业务路径 |
| 主词牌、辅词牌和原料摘要 | `model.GetDraft()` 的 `mainTokenId`、`auxTokenIds`、`ingredients` | 点击某项调用 `TakeOut`；“移出全部”对应 `model.Edit("clear")` |
| 故事书签 | `GetJournalStories()` | 选择故事后读取 `GetJournalPage(sourceLetterId)`；书签只来自已收到的故事 |
| 书页中的历史条目 | `GetJournalPage()` 的 `outcomes`、`attempts`、配方摘要、星级和状态 | `model.OpenAttempt(transactionId)` 选择历史；`GetAttempt(transactionId)` 读取完整记录 |
| 熬制入口 | `GetOrderSummary().actions.Preview`，以及当前主词等条件 | `model.Preview()` 从已保存草稿发起试做，等待结果后决定演出分支 |
| 待处理结果标记与结果纸页 | `GetOrderSummary().pending`，或按事务读取 `GetAttempt()` | 重开同一结果只导航，不再次 `Preview` |
| 结果页“重新配料” | `actions.Reset` | `model.Resolve(false)`：重置待处理结果、清空投料、保留设备与试做历史 |
| 结果页“确认发货” | `actions.Confirm` | `model.Resolve(true)`：成功保存后正式消耗与结算，一次发货 |
| 返回桌前及面板关闭 | 当前导航和面板状态 | 返回桌前用 `model.ReturnHome()`；关闭详情回炼药需 C 保留来源，只收起对应面板、不清草稿、不结算 |
| 现有日期金币卡 | `model.Refresh().live.gameFlow.day`、`.economy.currency` | 复用共用 HUD，展示正式状态 |

本轮点击详情方向的接口约束：订单纸使用 `model.Refresh().currentOrder.letterInstanceId` 绑定来信，复用 `model.Read(letterInstanceId)` 的既有阅读能力；不能将 `GetOrderSummary().sourceLetterId`（定义 ID）直接当实例 ID。记录书复用现有 journal 界面及上述查询；“配方书”是该物件的视觉叫法，现有功能为故事与试做记录。炼药来源的打开、关闭和返回路径交 C 实现，不把现有主页入口原样调用视为本流程已经成立。

用户允许 v03 效果图先示意名称及数量。四张原料纸签采用上行名称、下行数量的排版，均是后续程序排字参考；正式图层应交空白纸签，不能直接把带示意数的 v03 当正式运行底图。

| 原料 | 实际 ID | 容器建议 | 拖动时代表一份的形态 |
|---|---|---|---|
| 海盐 | `ing_sea_salt` | 浅盐碗及纸签 | 一小撮盐粒 |
| 夜露 | `ing_night_dew` | 玻璃露水瓶及纸签 | 一颗清晰的露珠 |
| 灰烬草 | `ing_ashen_herb` | 草药罐及纸签 | 一小束草叶 |
| 干花瓣 | `ing_dried_petal` | 花瓣碗及纸签 | 几片松散花瓣 |

| 夜露／×8 | 同上 | `model.Refresh().live.economy.ingredients.ing_night_dew or 0` |

| 干花瓣／×10 | 同上 | `model.Refresh().live.economy.ingredients.ing_dried_petal or 0` |

名称取 `content.ingredients` 中相应定义的 `name`。纸签数量表示正式库存，不是本锅已投份数，也不因投料视觉动作直接减一；已投份数取 `model.GetDraft().ingredients`，显示在本锅摘要。确认发货保存成功后，再从正式状态刷新库存。C／C2 负责绘制及刷新接入；本轮只记录映射，没有修改代码或验证动态刷新。

当前设备 `kit_old_cauldron` 提供 1 主词、2 辅词、2 份原料容量。四个容器是四种可选来源，不是四个投料槽。当前允许重复原料，两份海盐占满两份容量；同种原料在草稿中合并数量。

词卡操作必须使用来源实例 `tokenId`，不能用 `wordId` 替代。同名词可来自不同信件，但当前规则不允许同锅重复同名词；同一卡片也不能占多个位置。第一张进入空主词位，之后进入辅词位；移出主词后辅词不自动晋升，下一张投入的词补主词。

### 对素材设计有直接影响的限制

- `specialItemIds` 当前必须为空，非空会被拒绝。设备配置中的预留特殊槽不代表特殊物品已接入。
- 铜制锅虽在配置中存在，不因此自动增加换锅、购买设备或升级入口。后续设备变化时按真实配置调整摘要容量。
- 目前没有独立“装瓶”业务接口。空瓶、瓶塞可以是装饰或演出物件；若以后承载操作，须明确映射现有查看结果或确认发货，不新造结算步骤。
- 木架、桌布、装饰草药、炉火、瓶中装饰内容不各自新增玩法。容器看起来装满不代表真实库存充足。
- 选中词卡在发货前仍可用，以 `selectedRole` 表示本锅暂用；界面区分“已投入”和“已消耗”。原料库存同样只在确认发货后减少。
- 无当前订单时展示空态并复用已有来信入口，不伪造自由炼药订单。

### 药效与历史结果的数据区别

本次试做药效可取 `model.Preview()` 成功返回中的 `value.potion`，模型同时保留 `trialPotion`。重开或恢复当前待处理药效时，可通过 `session.order.GetView()` 成功结果中的 `value.pending.potion` 读取。

`GetOrderSummary().pending` 只投影事务、后续和评分；`GetAttempt()` 的历史记录提供 `recipeDisplay`、`followup`、`rating` 等，不直接包含完整 `potion`。不能把两个接口都当作药效详情查询。读取药效也不使用候选账本刷新正式金币或库存。

药液颜色、光点与药效属性之间尚无确认的视觉映射表。第一版分镜可画中性的短暂反馈，不用颜色编造后台属性或尚未发现的后续。

## 4 业务状态与前端表现

业务状态只有无订单 `idle`、可配料 `accepted`、待处理 `pending`；`idle` 是查询投影。“拖动中”“正在播放熬制动画”是前端表现状态，不新增持久业务阶段。

| 状态或事件 | 页面应表达什么 | 接口与保存边界 |
|---|---|---|
| 无订单 | 允许看词卡和记录，提示先从来信接单 | 不允许自由试做 |
| 可配料 | 可取料、投料、取回，显示订单条件和本锅摘要 | 成功编辑保存草稿，不消耗正式资源 |
| 拖动中 | 一份材料或一张词纸跟随指针，来源容器留在原位 | 指针移动不写档，不提前投料 |
| 松开到有效锅口 | 暂留投放影像，等待操作结果 | 一次明确提交调用一次 `Drop`，成功后演出 |
| 试做字面条件失败 | 显示接口提供的原因和可用药效信息，保留投料供调整 | `ok=true` 仍可能返回 `phase=accepted`；没有 pending、后续或新历史 |
| 试做保存成功 | 播放短熬制表现，再展示已保存结果 | 只有 `phase=pending` 才进入成功结果分支 |
| 待处理 | 保留结果标记，主入口恢复同一结果，锁定换料 | 关闭、返回、读历史不结算；采购等门禁以接口为准 |
| 重置成功 | 返回空配料状态，设备保留，记录书可看已重置记录 | 正式资源不回退、不消耗；历史标记 reset |
| 发货成功 | 显示已发货结果及正式状态变化 | 一次结算，历史标记 shipped |

C 使用 `GetOrderSummary().actions` 中的 `enabled`、`reasonCode`、`message` 控制操作；局部锅口提示不替代业务校验。保存失败保持原状态并显示原因；保存结果不确定时沿用现有恢复锁定流程。通知失败可能发生在业务已保存之后，不能据此重复提交或补发奖励。

## 5 三组关键分镜与动作说明

本节是 B 向 C 交接的表现规范。每组最终应有关键帧图片；本轮先记录文字分镜。时间均为 B 的初始建议，尚未做动画或设备验证，可在用户审图与 C 的实现约束反馈后调整。

### 原料入锅

以海盐为首个完整示例，其余原料共用动作逻辑，替换移动形态和落锅反馈。

| 帧 | 画面与动作 | 逻辑或结束条件 |
|---|---|---|
| M1 静置 | 盐碗在架上，纸签显示真实可用信息，锅口平静 | 没有隐形投料操作 |
| M2 取料 | 从碗中出现一小撮盐，轻微抬起并跟随指针；碗仍在原位 | 开始拖动，尚未调用 `Drop`；原料只产生视觉影像 |
| M3 对准锅口 | 指针进入锅口区域，锅沿出现柔和亮边 | 只表达可投放位置，不预告业务必然成功 |
| M4 松手 | 盐粒暂留在锅口上方，阻止同一操作重复提交 | 调用一次 `model.Drop("ingredient", ingredientId)` |
| M5 成功落锅 | 收到成功结果后，盐粒下落散开，药液轻微涟漪；配料签反映已保存份数 | 动画不扣库存、不再次调用接口；建议下落约 0.20 至 0.35 秒，余波约 0.35 至 0.60 秒 |
| M6 恢复 | 拖动影像和锅口提示消失，容器继续可取用 | 以最新草稿和门禁恢复操作 |

失败分支：放在锅外，或接口明确拒绝时，影像回到来源并消失，配方保持原样；必要时显示接口原因。退回时间建议约 0.15 至 0.25 秒。库存不足、容量已满和状态锁定分别显示真实原因。

点击容器也能完成一份投料：点击被识别为点击后调用同一 `Drop`，成功才播放从容器到锅口的短路径动画。拖动结束不能额外触发一次点击投料；具体手势阈值由 C 适配并验证。

夜露使用滴落和小涟漪，灰烬草使用少量草叶落下，花瓣使用轻微翻转。粒子范围留在锅附近，避免盖住词卡、书页和订单文字。

### 词纸入锅

| 帧 | 画面与动作 | 逻辑或结束条件 |
|---|---|---|
| W1 选取 | 左词盘中的具体来源纸卡轻微抬起，文字保持可读 | 绑定真实 `tokenId`，不凭同名字样重新找卡 |
| W2 移动 | 纸片跟随手指或鼠标，原位保持列表布局 | 尚未写草稿，滚动和拖动区分 |
| W3 对准 | 锅口柔和提示，纸片仍能辨认 | 松手时调用一次 `model.Drop("word", tokenId)` |

| 帧 | 画面与动作 | 逻辑或结束条件 |

## 6 辅助操作与中断处理

| 操作 | 表现方向 | 必须保留的业务含义 |
|---|---|---|
| 取回词卡 | 点击锅旁词纸缩影，成功后缩影淡去或回到左侧 | `TakeOut("word", tokenId)`；主位留空，不替辅词改身份 |
| 取回原料 | 点击配料签上的原料图样，成功后减少一份标记 | `TakeOut("ingredient", ingredientId)`；正式库存原本未扣，不演成新获赠原料 |
| 移出全部 | 配料纸签上的次级操作，使用可读文字或明确图形 | `model.Edit("clear")`，仅清当前草稿，和结果页重置不同 |
| 翻查历史 | 点故事书签或具体记录，阅读层展示完整内容 | 只读查询，不把历史结果替换为当前 pending，不因翻书发货 |
| 重新配料 | 结果页明确操作，成功后回到空投料状态 | `Resolve(false)`；保留设备与历史，不伪装成资源被倒掉 |
| 确认发货 | 结果页明确操作；瓶子或包裹可作成功后的表现 | `Resolve(true)`；保存成功才显示已发货和真实资源变化 |
| 返回或关闭 | 收起对应界面，清理临时拖动影像 | 保留已保存草稿或结果，不调用 Reset、Confirm |

中断按是否已提交、是否已保存区分：

1. 提交前拖到锅外、取消、失焦或切换场景：结束拖动并移除影像，不调用投料接口。
2. 指令已发出：前端不能仅因关闭页面就宣称操作未发生；执行窗口根据返回结果或现有恢复机制重新读取状态。
3. 保存成功但演出未完：可以结束视觉过程，下次按已保存草稿或 pending 恢复。演出被跳过不撤销业务，也不补发指令。
4. 尺寸变化、面板收起与滚动：清理失效的拖动坐标；不得让材料穿过不可见目标偷偷入锅。手机上以实际触控证据验收。

动作完成后应移除临时影像、锅口亮边和忙碌状态。缩放或淡入过程中，原料与词纸的阅读文字仍由程序保持清晰。

### 分层原则

拟拆分为室内与桌面干净背景、原料架、四个原料容器、四种一份原料的移动形态、炉体、药液与效果层、词盘与纸卡模板、记录书与书签、委托纸、配料纸签、操作与提示层。最终是否合并某些静态层，由确认图稿和 C 的绘制需求决定。

- 每个可移动或需独立隐藏的物件有独立素材；锅前沿如需遮挡落料，单独预留遮挡层。
- 词盘、书页或容器移开后可见的背景必须完整，不能露出烘焙副本、空洞或旧位置残影。
- 独立小物件紧凑裁切，保留必要阴影和少量透明留边；只有需整场配准的层才采用完整画布。
- 透明 PNG 的 alpha、半透明玻璃与伪棋盘格分开检查。玻璃需在实际目标背景上叠加看旧背景残留、白边和色块。
- 正式词文、订单、数量、日期、金币、星级和状态文字留给程序；纸面固定格线与列表容量也不烘焙。概念图若用示意文字，明确为示意，正式层中移除。
- 清楚标注原像素提取、局部修复或重新生成，不用重画冒充抠取；原素材无法满足条件时先说明冲突。
- 每次交付写明任务版本、参考图片、绝对路径、实际尺寸、透明及分层情况、实际检查结果、未完成项和接入对象。
